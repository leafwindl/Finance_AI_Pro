# 全项目数据流程图（带数据类型）

> 面向整个 `Finance_FASTAPI-Database` 工作区，描述 **Vue 前端 → FastAPI Gateway → Agent 平台 → 知识库** 全链路的数据流转，
> 并标注每一步传递的数据结构与其**字段类型**。
> 数据源：各模块源码（`Finance_Vue-main` / `Finance_AI_FASTAPI` / `Finance_Agent` / `Finance_Knowledge-main`）与 DB schema 迁移。
> 文档日期：2026-08-21

## 1. 公共协议（所有模块共用）

### 1.1 SSE 事件（Gateway→Vue 与 Agent→客户端 使用同一套事件）

| 事件 | data 字段（类型） |
|---|---|
| `progress` | `request_id:string` `conversation_id:string` `node:string` `message:string` |
| `delta` | `request_id:string` `conversation_id:string` `text:string` |
| `approval_required` | `request_id:string` `conversation_id:string` `approval_id:string` `answer:string` `options:list[Literal["approve","reject","revise"]]` |
| `completed` | `request_id:string` `conversation_id:string` `message_id:int` `answer:string` `metadata:object` |
| `error` | `request_id:string` `conversation_id:string` `code:string` `message:string` `retryable:bool` |

终止事件：`completed` / `approval_required` / `error`（每次请求只出现一个）。

### 1.2 DB 两个库（禁止混用表）

```text
knowledge_agent (Gateway 管理)          knowledge_base (KnowledgeBase 管理)
  users / user_sessions |                 documents(元数据+向量由ES存) / chunks(ES)
  conversations / messages |              kb_registry(sys_config) / KB01~KB06 分 schema
  uploaded_files           |
  requirement_review_records |
  kb_ingest_tasks(与KB互传)  |
```

## 2. 模块一：Finance_Vue-main（前端）

### 2.1 前端内部数据（状态/服务）
- `stores/user.js` — `user:{token:string, id:string, name:string, email:string}`
- `stores/agents.js` — `agents:Array<{agent_id, name, enabled, stateful}>`
- `services/api.js` — `apiFetch` 统一包裹 `{code:int, message:string, data:any}`
- `services/api/*`: `auth.js`(登录注册) `conversations.js`(会话) `knowledge.js`(知识库) `testcases.js`(用例)

### 2.2 前端 → Gateway 数据流

```
[共用交互组件]  ChatView / RequirementTracking / TestCaseEditor / KnowledgeGraphView
   │
   │  POST /api/v1/chat   (JSON, Accept: text/event-stream)
   ├──────────────────────────────► Gateway
   │  body: ChatRequest {
   │    query:string(1..5000)
   │    conversation_id:string|null
   │    agent_id: Literal[requirement-pre-review|ai-test-analysis|accounting-expert|business-analyst|ai-assistant]
   │    file_ids:list[string(1..64)] (≤5, 去重)
   │    client_message_id:string(默认 client_<uuid>)   ← 幂等去重
   │  }
   │
   │  POST /api/v1/chat/approve
   ├──────────────────────────────► Gateway
   │  body: ApprovalRequest { conversation_id:string(≤64), approval_id:string(≤128),
   │          decision:Literal[approve|reject|revise], reason:string(≤500) }
   │
   │  GET /api/v1/knowledge/graph | /kbs | /documents/{id}/subgraph | /content
   ├──────────────────────────────► Gateway
   │
   ◄──────────────────────────────┬ SSE: progress/delta/approval_required/completed/error
   │  渲染: FlowVisualizer / ChatMessages / ReviewReportCard / KnowledgeGraphCanvas
```

- 输入侧：文件经 `FileUploadInput.vue` → `POST /api/v1/files`（multipart）。
- 输出侧：`useTypewriter.js` 消费 `delta` 流式显示；`ReviewReportCard` 渲染 `completed.answer`(markdown)。

## 3. 模块二：Finance_AI_FASTAPI（Gateway，:8000）

### 3.1 网关内部数据流

```
                 ┌────────────────────────────────────────────────┐
   /api/v1/*     │  app/api/* (auth/chat/conversations/files)      │
  Vue ◄─────────►│  + knowledge.py (图谱)                          │
                 └───────┬────────────────────────────────────────┘
                         │
   [鉴权] app/api/auth.py ─ Cookie Session ─► user_sessions 表
                         │
   [DTO 校验] app/schemas/chat.py (上面的 ChatRequest / ApprovalRequest)
                         │
   [持久化] app/data_gateway/repositories/
        conversations.py ──► conversations / messages 表
        files.py         ──► uploaded_files 表
        reviews.py       ──► requirement_review_records 表
        kb_tasks.py      ──► kb_ingest_tasks 表
                         │
   [附件文本提取] app/knowledge_gateway/extraction.py
        TXT/PDF/DOCX/XLSX ──► text:string (≤200_000)
                         │
   [知识图谱] app/graph_gateway/neo4j.py ──► Neo4j (kb_documents 元数据在 PG knowledge_base)
                         │
   [调用 Agent] app/agent_gateway/client.py
        agent_headers() + POST {base_url}/v1/agent/chat
                         │
   [SSE 归一化] app/agent_gateway/sse.py (parse_sse/encode_sse)
                         ▼
   StreamingResponse ──► Vue
```

### 3.2 Gateway → Agent 请求（内部契约）

```
POST {AGENT_PLATFORM_URL}/v1/agent/chat   (JSON, Accept: text/event-stream)
body: {
  request_id:string,
  thread_id:string,              ← 复用 conversation_id
  user_id:string,
  agent_id: Literal[4 个 agent id],
  query:string(≤5000),
  attachments: [
    { file_id:string, filename:string, content_type:string,
      text:string(≤200_000) }    ← Gateway 提取后的文本
  ]
}
```

Agent 内部消息经 `ROUTE_MAP` 精确路由（`Finance_Agent/src/api/server.py`）：
| Gateway agent_id | Agent 内部目录 | 中文 |
|---|---|---|
| `requirement-pre-review` | agent1 | 需求预评审（有状态，支持审批）|
| `ai-test-analysis` | agent2 | 需求 AI 测试分析 |
| `accounting-expert` | agent3 | 测试用例评审 |
| `business-analyst` | agent4 | 测试步骤生成 |

### 3.3 数据库类型（knowledge_agent 库）

**users** `user_id:VARCHAR(32)PK, name:VARCHAR(64)UQ, email:VARCHAR(256)UQ, password:VARCHAR(128), created_at:TIMESTAMPTZ`

**user_sessions** `session_id:VARCHAR(64)PK, user_id:FK, expires_at/revoked_at/last_seen_at:TIMESTAMPTZ`

**conversations** `conversation_id:VARCHAR(64)PK, user_id:FK, agent_id:VARCHAR(64), title:VARCHAR(256), created_at/updated_at:TIMESTAMPTZ`

**messages** `message_id:SERIAL PK, conversation_id:FK, role:CHECK(user|assistant), content:TEXT, request_id:VARCHAR(64), client_message_id:VARCHAR(128), status:CHECK(completed|failed), error_code:VARCHAR(64), metadata:JSONB, created_at:TIMESTAMPTZ`

**uploaded_files** `file_id:VARCHAR(64)PK, user_id:FK, filename:VARCHAR(256), content_type:VARCHAR(128), extension:VARCHAR(16), size_bytes:BIGINT, storage_path:VARCHAR(512), status:CHECK(ready|expired), expires_at/created_at:TIMESTAMPTZ`

**requirement_review_records** `review_id:BIGSERIAL PK, conversation_id:FK, report_message_id:FK, approval_id:VARCHAR(128), report_content:TEXT, decision:CHECK(pending|approve|reject|revise), rejection_reason:VARCHAR(500), created_at/decided_at/updated_at:TIMESTAMPTZ, UNIQUE(conversation_id,approval_id)`

**kb_ingest_tasks** `task_id:VARCHAR(64)PK, file_id, user_id:FK, filename:VARCHAR(256), status:CHECK(processing|completed|failed|rolled_back), stage:CHECK(saved|ingesting), percent:INTEGER, kb_code:VARCHAR(8)(可空), total_chunks:INTEGER, doc_id:VARCHAR(128), error_code:VARCHAR(64), error_message:TEXT, blocks:JSONB, kb_distribution:JSONB, created_at/updated_at/expires_at:TIMESTAMPTZ`

## 4. 模块三：Finance_Agent（Agent 平台，:8101）

统一入口 `src/api/server.py`：根据 `agent_id` 精确路由到四个 Agent，各自内部是 LangGraph 状态机，输出/接受的落点仍是统一 SSE。

### 4.1 Agent 平台外层数据流

```
Gateway :8000
   │  POST /v1/agent/chat  {request_id, thread_id, user_id, agent_id, query, attachments[]}
   ▼
src/api/server.py  gateway_chat()
   │  ROUTE_MAP[agent_id]
   ├─ agent1 → 需求预评审     （有状态：pending_approval + 内存审批，支持 /v1/agent/approve 恢复）
   ├─ agent2 → 需求分析
   ├─ agent3 → 用例评审
   └─ agent4 → 步骤生成
   │
   │  需要知识时: POST {KB_BASE_URL}/api/v1/search
   ▼
   SSE → Gateway (progress/delta/approval_required/completed/error)
```

### 4.2 各 Agent 状态类型（LangGraph Shared State）

**① agent1 需求预评审 `RequirementState`（有状态/审批）**
```
requirement_input:string, file_content:string, file_name:string
requirement_analysis:{summary:string, business_context:string, functional_scope:string,
                      affected_systems:list, constraints:list, completeness_score:float, missing_info:list}
six_points:{background,business_objective,user_scope,functional_requirements,
            non_functional_requirements,implementation_impact:string,
            completeness_score:float, missing_items:list}
biz_keywords/test_keywords/regulatory_keywords/history_keywords:string
kb_code_list:list
business_query/test_query/regulatory_query/history_query/all_query:string
knowledge_context:string, retrieved_documents:list
retrieval_queries:dict, risk_analysis:{...}
final_output:string  ← 审批通过后的报告正文
```

**② agent2 需求分析 `AgentState`**
```
messages:Sequence[AnyMessage](add_messages)
biz_keywords/test_keywords/regulatory_keywords:string, kb_code_list:list[str]
biz_query/test_query/stock_query/all_query:string|null
biz_result/test_practice_result/test_standard_result/regulatory_result:list[Document]
aggregated_context:string
```
Graph：`extract_keywords → convert_keywords →(all_query 空?)→ retrieve_all(三路并行) → rag_response | chat_response`

**③ agent3 用例评审 `ReviewState`**
```
query:string; keyword_raw:string; keywords:dict
standard_context/spec_context/history_context:string
retrieval_context:dict;  review_report:dict(18项+summary)
report_text:string;  pass_flag:bool(≥80%);  checklist:list
```

**④ agent4 步骤生成 `WorkflowState`**
```
query:string; test_case:dict|null; doc_content:string
keywords:list[str]; kb_keywords:dict[str,list[str]]
kb_task_list:[{kb_codes:list[str], query:string, need_search:bool}]
rag_docs:list[str]; llm_json_raw:string; parse_data:list|null
is_success:int(1/0); output_text:string; error_msg:string; progress_msg:string
```

### 4.3 Agent → 知识库检索请求

```
POST /api/v1/search
body: { query:string(≤5000), kb_codes:list[string]≤10(空=全库),
        top_k:int(1..50, 默认10), expand_k:int(0..20, 默认3), request_id:string }
```

## 5. 模块四：Finance_Knowledge-main（知识库，:8002 等）

### 5.1 检索（searcher）数据流

```
Agent :8101
   │  POST /api/v1/search (上面的 SearchRequest)
   ▼
searcher/kb_search_server.py  run_pipeline() 三段式检索
   │
   ├─► Neo4j 图谱关键词扩展 (expand_k>0)
   ├─► Elasticsearch BM25 + 向量混合检索 (RRF 融合)   index: knowledge_chunks_{kb_code}
   │    向量: BAAI/bge-large-zh-v1.5  (SentenceTransformer, normalize)
   └─► PostgreSQL knowledge_base: documents 元数据溯源 (kb_code→schema/table)
   ▼
响应 SearchResponse {
  query:string,
  results:[ { content:string, score:float(RRF),
              bm25_score:float|null, vector_score:float|null(0~2 余弦+1),
              metadata:{kb_code,title,heading,doc_id,chunk_id,source} } ],
  trace:{core_keywords, expanded_keywords, result_count, bm25_count, vector_count}
}
```

### 5.2 入库（writer/ingest）数据流

```
upload.py / services/ingest_service.py
   │ 上传: .md/.txt/.pdf/.docx (≤10MB)
   ▼
parser/ (docx/pdf/txt_parser + cleaner + config.yaml 标题/编码规则)
   ▼ 纯文本 → 结构化 Markdown (按 heading 切块)
classifier/ (segmenter 切片 → LLM 分类 → 每块映射 KB01~KB06)
   ▼
writer/kb_ingest((_batch).py)  三条线写入：
   ├─► PostgreSQL knowledge_base: <schema>.documents  (doc_hash:TEXT PK, title:
   │        source_file:TEXT, file_size_bytes:BIGINT, file_created/file_modified/updated_at:TIMESTAMPTZ,
   │        word_count/char_count:INTEGER, meta_fields:JSONB)  ← 元数据
   ├─► Elasticsearch: knowledge_chunks_{kb_code}  ← 切片正文+向量 (text+embedding)
   └─► (脚本) Neo4j: 实体关系图 (offline: build_neo4j_graph.py / neo4j_extract.py)
   │
   └─► 回写 Gateway: kb_ingest_tasks 表进度 + needs_graphrag_rebuild 标记
```

> ⚠️ **已知事项：图谱不会随上传自动更新**。上传入库只实时写 PG + ES，Neo4j 实体图不在入库链路中更新，
> 仅由 `status_manager.py` 把 `knowledge_base.sys_config.rebuild_flags.needs_graphrag_rebuild` 置为 true
> （消费方 8201 rag_service 本机未运行，也没有自动调度器）。探索知识图谱页只读 Neo4j，
> 因此新上传文档要**手动重建**后才会出现在图谱里：
>
> ```bash
> cd Finance_Knowledge-main/Finance_ai_team_KnowledgeBase/writer
> python neo4j_extract.py   # 读 ES 新chunk → DeepSeek 抽实体/关系 → Neo4j（耗时：单文档几十秒~分钟）
> python neo4j_index.py     # 建 chunks + PART_OF 索引
> python neo4j_relink.py    # 关系重连
> python neo4j_retry.py     # 失败重试
> ```
>
> 重建后前端图谱页点"刷新数据"（或重新进入页面）即可看到新节点。

知识库编号映射（`Finance_AI_FASTAPI/app/data_gateway/repositories/knowledge_docs.py`）：
`KB01 系统业务 / KB02 法规合规 / KB03 历史需求评审案例 / KB04 标准测试用例 / KB05 历史缺陷测试经验 / KB06 测试规范模板`

## 6. 端到端一张图（主聊天链路，含类型）

```
[Vue]  ChatView
  │ ChatRequest{query:string, agent_id:enum, file_ids:list[string], client_message_id:string}
  ▼
[Gateway] /api/v1/chat ──鉴权──► user_sessions
  │ extract_text(file)→string ; insert_user_message→messages
  ▼ InternalChatRequest{request_id, thread_id, user_id, agent_id, query, attachments[]}
[Agent] router ROUTE_MAP[agent_id] (agent1..4)
  │ ──POST /api/v1/search SearchRequest{query, kb_codes[], top_k, expand_k}──► [KnowledgeBase]
  │    ◄── SearchResponse{results:[{content,score,bm25_score,vector_score,metadata}]}
  │ LangGraph State (RequirementState/AgentState/ReviewState/WorkflowState)
  ▼ SSE: progress→(delta*)→completed{answer,message_id} | approval_required | error
[Gateway] 落库 messages(status,metadata JSONB)
  │ 补 conversation_id + message_id；requirement-pre-review 另写 requirement_review_records
  ▼ SSE
[Vue]  ChatMessages / ReviewReportCard
```

## 7. 跨服务透传字段（日志/追踪）

| 字段 | 类型 | 说明 |
|---|---|---|
| `request_id` | string | 一次用户请求，Gateway 生成 |
| `conversation_id` / `thread_id` | string | 一次业务会话，互为镜像 |
| `user_id` | string | 内部用户标识 |
| `agent_id` | enum | 实际选择的智能体 |
