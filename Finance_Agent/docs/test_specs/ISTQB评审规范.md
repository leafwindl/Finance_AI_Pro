# ISTQB 测试用例评审规范

## 一、覆盖完整性
- 功能场景覆盖：每个功能点至少有一条正向用例
- 正常流程覆盖：主流程的每一步都有对应验证
- 异常流程覆盖：网络异常、超时、服务不可用等场景
- 边界条件覆盖：数值边界、字符串长度、日期边界

## 二、规则正确性
- 业务规则正确：预期结果与需求文档一致
- 输入限制完整：所有输入字段都有类型/范围/格式校验
- 权限和状态校验覆盖：不同角色、不同状态下的操作权限

## 三、可执行性
- 前置条件明确：环境、数据、权限等前置条件清晰可执行
- 测试意图明确：测试场景和测试目标是否清晰
- 测试数据明确：使用的测试数据在用例中明确列出

## 四、预期结果可观察性
- 预期结果具体：不是"系统正常"而是"提示XX，页面跳转到XX"
- 可验证成功或失败：有明确的判定标准

## 五、用例一致性
- 测试步骤和预期结果匹配：步骤描述的操作与预期能对应
- 输入输出一致：输入数据应在步骤中体现，输出结果明确

## 六、用例唯一性
- 无重复测试点：不与已有用例覆盖相同场景
- 不与已有用例重复：同一功能同一场景不写多条

## 七、历史缺陷风险
- 覆盖历史高风险问题：参考历史缺陷库中类似功能的缺陷
- 无类似缺陷遗漏：常见缺陷模式（空值、并发、权限等）已覆盖
