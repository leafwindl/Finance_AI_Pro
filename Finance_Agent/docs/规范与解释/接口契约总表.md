## 0. 架构总览（一张图）

```text
Browser / Vue(5173)
  │  credentials:'include'（Cookie Session）
  ▼
FastAPI Gateway(8000) ── /api/v1/* ──► 用户/会话/消息/文件 落库 knowledge_agent(PG)
  │  POST /v1/agent/chat（内部协议，X-Agent-Token 可选）
  ▼
LangGraph Agent Platform(8101) ── 按 agent_id 路由 5 个智能体
  │  POST /api/v1/search（KB REST）
  ▼
KnowledgeBase(8002) ──► Elasticsearch(9200) / PostgreSQL(5432)
```

**边界（铁律）**：
- 浏览器只访问 Vue + Gateway；禁止直连 Agent / KB / DB
- Agent 不接收浏览器 Cookie、不自行鉴权浏览器身份、不接收本地文件路径（只收 Gateway 提取后的文本附件）
- 模型（DeepSeek）、知识库、数据库均在服务端内部调用

## 1. 调用与鉴权边界

| 项 | 规则 |
|---|---|
| 鉴权 | HttpOnly Session Cookie；前端必须 `credentials: 'include'` |
| Cookie 内容 | 只存随机 token 的 SHA-256 摘要（不存明文） |
| 生产 | HTTPS 必须 `SESSION_COOKIE_SECURE=true` |
| 内部鉴权 | Agent 8101 可选 `AGENT_API_TOKEN`（配置后请求必须带 `X-Agent-Token`，否则 401；未配置放行=向后兼容） |

---

## 2. 通用约定

- 普通请求/响应：UTF-8 JSON
- 聊天响应：`text/event-stream`（SSE）
- 时间：带时区 ISO 8601
- 所有会话/消息/文件查询强制带当前 `user_id` 所有权条件
- 首次聊天由 Gateway 创建会话；前端不手工建会话/写消息
- 客户端每次发送生成唯一 `client_message_id`（同会话幂等）
- 响应头 `X-Request-ID` 关联 Gateway 日志
- 校验错误：`{"detail": "..."}`；结构化错误：`{"error": {"code","message","retryable"}}`

## 5. 文件上传

```http
POST /api/v1/files/upload   （multipart/form-data）
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `file` | 是 | 原始文件 |
| `agent_id` | 否 | 兼容字段；文件属于用户，不绑定 Agent |

成功 201：

```json
{"file_id":"file_...","filename":"需求说明.md","content_type":"text/markdown","size":1024,"status":"ready"}
```

**限制**：
- 单文件默认最大 10 MB
- 支持 `.pdf` `.docx` `.xlsx` `.md` `.txt` `.csv` `.json`
- 超过 `UPLOAD_TTL_SECONDS` 不能用于聊天
- 只能引用当前用户 `ready` 且未过期的 `file_id`
- 单次聊天最多 5 个文件，提取文本总长受配置限制

### 5.1 OCR 图片支持（新增契约，v2.0）

> **实现方：Gateway（8000）**。Agent 层只收文本，不感知 OCR。
> 完整实现指引见《OCR实现方案.md》（同目录，给 Gateway 对接方）。

| 项 | 规则 |
|---|---|
| 新增支持的 MIME | `image/png` `image/jpeg` `image/gif` `image/webp` |
| 提取流程 | Gateway 收到图片 → OCR 引擎识别 → 文本进入 `attachments[].text`（与普通文件同通道） |
| OCR 引擎 | **实现方自选**（建议：MinerU 在线 API / PaddleOCR 本地 / 其他，需在 Gateway `.env` 配置开关） |
| 失败降级 | OCR 失败 → `attachments[].text` 为空字符串 + `metadata.ocr_failed: true`，不阻塞聊天 |
| 上传响应 | `content_type` 保留原始图片 MIME；`status` 仍为 `ready` |
| 大小限制 | 图片单张 ≤ 5 MB（小于普通文件 10MB，控制 OCR 成本） |

**实现方案（给 Gateway 的参考）**：
1. `app/knowledge_gateway/extraction.py` 增加 `image/*` 分支 → 调 OCR 客户端
2. `.env` 新增：`OCR_PROVIDER`（`mineru` / `paddle` / `none`）、`OCR_API_KEY`、`OCR_TIMEOUT_SECONDS`
3. 附件文本拼入 query / `file_content` 的现有逻辑不变（agent5 的 doc_qa 意图自动生效）
4. 契约测试：上传截图 → 聊天时 `attachments[].text` 含 OCR 文本

## 6. 流式聊天（核心）

```http
POST /api/v1/chat
Content-Type: application/json
Accept: text/event-stream
```

```json
{
  "query": "分析这份需求是否完整",
  "conversation_id": null,
  "agent_id": "requirement-pre-review",
  "file_ids": ["file_..."],
  "client_message_id": "7d64ddd4-..."
}
```

| 字段 | 必填 | 约束 |
|---|---|---|
| `query` | 是 | 1～5000 字符 |
| `conversation_id` | 否 | 首次 `null`，后续用返回值 |
| `agent_id` | 是 | §4 五个稳定 ID 之一 |
| `file_ids` | 否 | 最多 5 个，服务端去重 |
| `client_message_id` | 建议 | 1～128，同会话幂等 |

### 6.1 SSE 事件协议（Gateway → 前端）

| 事件 | 触发 | data 关键字段 | 是否终止 |
|---|---|---|---|
| `progress` | 每个节点开始 | `request_id`, `conversation_id`, `node`, `message` | 否 |
| `delta` | 流式文本 | `request_id`, `conversation_id`, `text` | 否 |
| `completed` | 流程结束 | `request_id`, `conversation_id`, `message_id`, `answer`, `metadata` | **是** |
| `approval_required` | 仅 agent1 出报告后 | `request_id`, `thread_id`, `approval_id`, `answer`, `options` | **是** |
| `error` | 任一步失败 | `request_id`, `conversation_id`, `code`, `message`, `retryable` | **是** |

**规则**：
- 一次请求只能出现**一个**终止事件（completed / approval_required / error）
- `completed.answer` 是最终权威文本（delta 拼接只是过程展示）
- Gateway 只在 assistant 消息成功落库后发 `completed`
- 事件可能跨 HTTP 分块边界，调用方必须**按空行切分 SSE**（不能一次网络读取=一个事件）
- 未收到终止事件前不要判定失败（progress/delta 数量不固定）

**SSE 示例（agent5）**：

```text
event: progress
data: {"request_id": "demo1", "conversation_id": "conv_001", "node": "intent_recognition", "message": "正在理解你的意图..."}

event: delta
data: {"request_id": "demo1", "conversation_id": "conv_001", "text": "你好！"}

event: completed
data: {"request_id": "demo1", "conversation_id": "conv_001", "message_id": 42, "answer": "你好！", "metadata": {"intent": "chat"}}
```

### 6.2 各 agent 的 progress 节点与 metadata（流程图/定位依据）

| agent_id | progress 节点序列 | completed.metadata |
|---|---|---|
| `requirement-pre-review` | requirement_parser → keyword_extractor → kb_router → knowledge_retrieval → six_points_eval → risk_assessment → report_generator | —（停在 approval_required，options=["approve","reject","revise"]） |
| `ai-test-analysis` | extract_keywords → convert_keywords → (retrieve_all → rag_response / chat_response) | `{}` |
| `accounting-expert` | keyword → (standard/spec/history_retrieval 三路并行) → retrieval_merge → review_generate → score | `pass_flag`, `coverage`, `checklist` |
| `business-analyst` | extract_keyword_node → kb_route_node → knowledge_retrieve_node → llm_gen_json_node → json_to_python_node → (gen_markdown_node / gen_error_node) | `retrieval_count`, `steps` |
| `ai-assistant` | intent_recognition → (kb_retrieve) → answer_generate / transfer_agent | `intent`（+`transfer`：intent=transfer_confirm 时带 `{target, query}` 跳转指令） |

> **流程可视化约定（v2.0）**：前端进度条/流程图的节点名**必须与上表一致**（与 server.py `*_NODE_PROGRESS` 映射表同源）。改 agent 图加节点时，必须同步：① server.py 进度映射 ② 本表 §6.2 ③ 前端流程图配置——三处一致，防"假进度"。

### 6.3 流错误码（统一）

| code | 含义 | retryable |
|---|---|---|
| `agent_unavailable` | 无法连接 Agent | true |
| `agent_timeout` | Agent 响应超时 | true |
| `agent_upstream_error` | Agent 返回非成功状态 | true |
| `agent_stream_incomplete` | Agent 流意外结束 | true |
| `agent_invalid_response` | Agent 完成事件没有答案 | false |
| `knowledge_base_unavailable` | Agent 无法检索知识库 | true |
| `model_authentication_failed` | 大模型鉴权失败 | false |
| `model_connection_lost` | 模型连接断开 | true |
| `agent_execution_failed` | 智能体执行失败 | true |
| `agent_result_invalid` | 智能体返回无效结果（仅 agent4） | false |
| `gateway_stream_error` | Gateway 处理流未知错误 | true |

## 8. agent5 多轮记忆（新增契约，v2.0）

> 记忆只存 Agent 侧 PostgreSQL（`langgraph-checkpoint-postgres` 建表）；**上传 Git 的只有代码与依赖清单，不含任何对话数据**。各部署方用自己的 PG，互不干扰。

| 项 | 规则 |
|---|---|
| 记忆粒度 | **全状态记忆**（checkpointer 存完整 State，含 retrieval_context；喂给 LLM 的仍为 handler 截断后的最近 N 轮） |
| 会话隔离 | 每个 `thread_id` 独立记忆（多会话天然支持） |
| 持久化 | **PostgresSaver**（PG 建 `checkpoints` 表；Agent 重启不丢） |
| 触发链路 | 前端 convId → conversation_id → Gateway `thread_id=conversation_id`（已实现）→ Agent checkpointer 按 thread_id 读写 |
| 前端多会话 UI | 会话列表/切换 = 前端开发项（v2.0 不冻结前端实现，只冻结后端契约） |

**多会话语义（给前端）**：同一 `conversation_id` 的连续请求共享记忆；新建会话 = 新 conversation_id = 全新记忆。前端"多会话列表"就是对 `/api/v1/conversations?agent_id=ai-assistant` 的列表化展示 + 点击切换 convId。

> ⚠️ **字段名约定（前端必读）**：Agent 内部叫 `thread_id`，**网关归一化后的事件字段是 `conversation_id`**（§9"网关重新解析并白名单转发"）。前端保存会话 ID 必须读 **`data.conversation_id`**（兼容可 `data.conversation_id ?? data.thread_id`），并持久化到 localStorage（刷新不丢）——**记忆数据在 PG 永存，前端负责保管"会话编号这把钥匙"**。

## 9. Gateway → Agent 内部协议

```http
POST /v1/agent/chat
Content-Type: application/json
Accept: text/event-stream
```

```json
{
  "request_id": "req_...",
  "thread_id": "conv_...",
  "user_id": "4af5c21b583743da",
  "agent_id": "ai-assistant",
  "query": "你好，帮我看看这个",
  "attachments": [
    {"file_id":"file_...","filename":"截图.png","content_type":"image/png","text":"(OCR 提取的文本，图片由 Gateway 识别)"}
  ]
}
```

| 字段 | 类型 | 必填 | 规则 |
|---|---|---|---|
| request_id | string | 是 | ≤128；SSE 回显 |
| thread_id | string | 是 | ≤128；**多轮记忆 key**，同一会话保持一致 |
| user_id | string | 否 | 默认 `"default"`，≤128 |
| agent_id | string | 是 | 五选一（§4） |
| query | string | 是 | 1~5000 |
| attachments | array | 否 | ≤5；每项 `{file_id, filename, content_type, text≤200_000}` |

**规则**：
- `thread_id` = Gateway `conversation_id`
- Agent 不接收浏览器 Cookie / 不鉴权浏览器身份 / 不收本地文件路径
- Agent 返回 progress / delta / completed / error（+agent1 的 approval_required）
- Gateway 重新解析并白名单转发事件，不盲目透传
- `GET /health` 只查进程存活，不调 LLM

### 9.1 审批（agent1 专用）

```http
POST /v1/agent/approve
```

```json
{"request_id":"req_...","thread_id":"conv_...","user_id":"...","agent_id":"requirement-pre-review","approval_id":"approval_...","decision":"approve|reject|revise","reason":"..."}
```

| HTTP | code | 说明 |
|---|---|---|
| 200 | — | `{ok,thread_id,approval_id,decision}` |
| 409 | approval_not_pending | 无待处理审批 |
| 403 | — | 审批信息与待处理状态不匹配 |
