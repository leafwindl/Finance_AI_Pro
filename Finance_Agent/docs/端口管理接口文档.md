# 端口管理接口文档

> ⚠️ **过时**：`src/port_manager/` 为过时子系统（单进程 8101 架构已废弃多端口，见 `docs/规范与解释/架构与编码规范.md`），新开发禁止依赖。本文件保留仅作历史参考。

> 面向 FastAPI 服务开发者（各智能体接入方）

## 概述

端口管理器（Port Manager）是平台统一的端口分配与生命周期管理服务，运行在主 API 网关进程内（默认 `http://localhost:8000`）。各智能体在启动时向它申请端口，运行期间定期发送心跳，关闭时释放端口。

### 核心原则

- **先申请，后使用** — 不允许硬编码端口，必须通过接口获取
- **租约机制** — 分配后有 300 秒租约，超时未心跳则自动回收
- **统一响应** — 所有接口返回 `{code, message, data}` 结构，`code=0` 表示成功

---

## 统一响应格式

```json
{
  "code": 0,
  "message": "操作成功",
  "data": { ... }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `code` | int | 业务错误码，**0 = 成功**，非 0 = 失败 |
| `message` | string | 人类可读的描述 |
| `data` | object/null | 响应数据，失败时为 null |

> **重要**：调用方应以 `code` 字段判断业务是否成功，不要依赖 HTTP 状态码。

## 接口列表

### 1. 申请端口

```http
POST /v1/port/apply
Content-Type: application/json
```

**请求体：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `agent_name` | string | ✅ | 智能体标识：`agent1` / `agent2` / `agent3` / `agent4` |
| `agent_type` | string | ✅ | 智能体类型：`requirement_review` / `requirement_analysis` / `case_review` / `step_generation` |
| `token` | string | ✅ | 身份令牌（向平台管理员获取） |
| `requested_port` | int | ❌ | 指定端口号，不传则由系统自动分配 |
| `metadata` | object | ❌ | 附加信息（版本、主机名等） |

**请求示例：**

```bash
curl -X POST http://localhost:8000/v1/port/apply \
  -H "Content-Type: application/json" \
  -d '{
    "agent_name": "agent1",
    "agent_type": "requirement_review",
    "token": "agent1-port-token",
    "metadata": {"version": "1.0.0", "host": "127.0.0.1"}
  }'
```

**成功响应 `200`：**

```json
{
  "code": 0,
  "message": "操作成功",
  "data": {
    "agent_name": "agent1",
    "agent_type": "requirement_review",
    "assigned_port": 8101,
    "allocated_at": "2026-07-29T02:24:30.590993+00:00",
    "lease_timeout_seconds": 300,
    "heartbeat_interval": 30
  }
}
```

| 返回字段 | 说明 |
|----------|------|
| `assigned_port` | 已分配的端口号，**Agent 应在此端口启动服务** |
| `lease_timeout_seconds` | 租约时长（秒），超时未心跳端口将被回收 |
| `heartbeat_interval` | 建议心跳间隔（秒），约 `lease_timeout / 10` |

**常见失败：**

| code | 说明 | 处理建议 |
|------|------|----------|
| 3002 | 已注册端口，重复申请 | 先调 release 再申请，或直接复用已分配端口 |
| 4001 | Token 无效 | 检查 `token` 是否正确 |
| 2005 | 端口池耗尽 | 联系平台管理员扩容 |

### 2. 发送心跳

```http
POST /v1/port/heartbeat
Content-Type: application/json
```

申请成功后**必须**按 `heartbeat_interval` 间隔定期发心跳，否则端口会被自动回收。

**请求体：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `agent_name` | string | ✅ | 智能体标识 |
| `port` | int | ✅ | 已分配的端口号 |
| `token` | string | ✅ | 身份令牌 |
| `status` | object | ❌ | 当前运行状态（如 `{"running": true, "pid": 12345}`） |

**请求示例：**

```bash
curl -X POST http://localhost:8000/v1/port/heartbeat \
  -H "Content-Type: application/json" \
  -d '{
    "agent_name": "agent1",
    "port": 8101,
    "token": "agent1-port-token",
    "status": {"running": true, "pid": 12345}
  }'
```

**成功响应 `200`：**

```json
{
  "code": 0,
  "message": "操作成功",
  "data": {
    "port": 8101,
    "agent_name": "agent1",
    "heartbeat_received": true,
    "next_heartbeat_in": 30
  }
}
```

**常见失败：**

| code | 说明 |
|------|------|
| 2004 | 端口未注册（可能已被回收） |
| 3003 | 端口不属于该 Agent |

### 3. 释放端口

```http
POST /v1/port/release
Content-Type: application/json
```

Agent 关闭时调用，主动归还端口。

**请求体：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `agent_name` | string | ✅ | 智能体标识 |
| `port` | int | ✅ | 要释放的端口号 |
| `token` | string | ✅ | 身份令牌 |

**请求示例：**

```bash
curl -X POST http://localhost:8000/v1/port/release \
  -H "Content-Type: application/json" \
  -d '{
    "agent_name": "agent1",
    "port": 8101,
    "token": "agent1-port-token"
  }'
```

**成功响应 `200`：**

```json
{
  "code": 0,
  "message": "操作成功",
  "data": {
    "released_port": 8101,
    "agent_name": "agent1"
  }
}
```

## 完整接入示例（Python）

推荐使用平台提供的 `PortAgentClient`，封装了申请、心跳、释放的完整生命周期：

```python
from src.port_manager import PortAgentClient

client = PortAgentClient(
    agent_name="agent1",
    token="agent1-port-token",
    manager_url="http://localhost:8000",
)

# 1. 启动时申请端口
port = await client.acquire()
print(f"分配端口: {port}")

# 2. 在分配的端口上启动你的 FastAPI 服务
# uvicorn.run(app, port=port, ...)

# 3. 关闭时释放端口（心跳自动停止）
await client.release()
```

如果不方便引入模块，也可以直接用 `httpx` 或 `requests` 调用 HTTP 接口实现相同逻辑。

## 端口分配策略

每个智能体有独立的偏好端口范围，申请时不指定端口则在该范围内自动分配：

```
agent1 (需求评审)  →  8101 — 8199  (99 个)
agent2 (需求分析)  →  8200 — 8299  (100 个)
agent3 (用例评审)  →  8300 — 8399  (100 个)
agent4 (步骤生成)  →  8400 — 8499  (100 个)
备用的共享范围             8500 — 8500  (1 个)
```

偏好范围用完后，自动从全局池扫描。总池范围可通过环境变量 `PORT_POOL_START` / `PORT_POOL_END` 调整。

## 租约与心跳

```
 ┌──────────┐     申请端口      ┌──────────────┐
 │  Agent   │ ────────────────→ │ Port Manager │
 │          │ ←── 分配 8101 ── │              │
 │  启动在   │                   │  租约 300s   │
 │   :8101  │ ─── 心跳(30s) ──→ │              │
 │          │ ←── heartbeat_ok  │  倒计时重置   │
 │          │       ...          │              │
 │  关闭    │ ─── 释放端口 ────→ │  端口回收     │
 └──────────┘                   └──────────────┘
```

- **心跳间隔**：30 秒（由 `heartbeat_interval` 返回）
- **租约时长**：300 秒（5 分钟）
- **自动回收**：超过租约时长未收到心跳，端口自动释放
- **建议**：连续 3 次心跳失败应检查网络或申请新端口
