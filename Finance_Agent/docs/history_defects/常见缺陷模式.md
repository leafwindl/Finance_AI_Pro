# 常见缺陷模式

## 1. 输入缺失
**症状**：必填字段为空、null 或未传入时，系统未做校验直接处理。
**案例**：密码为空直接登录成功、金额未填导致转账异常。
**建议**：每个输入字段都应有空值/边界值测试用例。

## 2. 边界条件遗漏
**症状**：数值范围、字符串长度、日期区间的边界值未覆盖。
**案例**：金额输入 0.01 和 99999999 均报错、日期选择 2月30日通过校验。
**建议**：边界值至少覆盖 最小值-1、最小值、最大值、最大值+1 四个点。

## 3. 并发冲突
**症状**：同一用户同时提交两次请求，导致重复操作。
**案例**：连续点击两次"提交"，生成两条重复订单。
**建议**：所有写操作必须加幂等校验。

## 4. 权限越权
**症状**：低权限用户访问高权限接口。
**案例**：普通用户直接调用管理员 API 成功删除数据。
**建议**：每个接口都要验证角色权限。

## 5. 异常覆盖不足
**症状**：仅覆盖正常流程，异常流程缺失。
**案例**：网络超时、数据库连接失败、第三方接口返回500 等场景未测试。
**建议**：每个核心流程至少设计 3 条异常用例。
