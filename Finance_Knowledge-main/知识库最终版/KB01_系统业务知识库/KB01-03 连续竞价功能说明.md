## 功能名称和目的
**功能名称**：HOSE风格连续竞价匹配引擎（Continuous Matching Engine with HOSE Rules）  
**目的**：在模拟证券交易系统中，依据越南HOSE交易所连续竞价规则（剔除ATO/ATC及午休），实现市价单与限价单的实时价格发现、订单匹配与交易执行，确保价格形成符合供需博弈逻辑，并支撑前端行情展示（Bảng giá）。

## 使用角色或调用方
- **终端用户**：投资者（通过UI提交Market/Limit Order）  
- **系统组件**：前端交易界面、订单网关（Order Gateway）、行情推送服务（Quote Feed）  
- **内部调用方**：Matching Engine自身（递归扫描Book Order）、Transaction Logger（持久化成交记录）

## 操作入口
- Web端：交易面板 → 选择股票代码 → 输入数量/价格（限价单）或仅数量（市价单）→ 点击“买入”/“卖出”按钮  
- API端：`POST /api/orders`（请求体含`{symbol, side: "BUY"/"SELL", type: "MARKET"/"LIMIT", price?, quantity}`）

## 前置条件
1. 系统已加载当日基础数据：  
   - 各股票前一交易日收盘价（作为今日参考价）  
   - 股票代码有效性校验通过（存在于证券池）  
2. 用户账户具备足够可用资金（买入）或持仓（卖出）  
3. 当前处于模拟交易时段：`9:15–11:30` & `13:00–13:30`（周一至周五，不含节假日）  
4. 订单价格满足`参考价 × (1±7%)`约束（即`price ≥ refPrice×0.93` 且 `price ≤ refPrice×1.07`），限价单强制校验，市价单隐式满足（因匹配逻辑保证成交价必在涨跌幅内）

## 正常处理
|步骤|操作/输入|系统处理|输出|
|---|---|---|---|
|1|用户提交Market Buy Order（如：VNM, BUY, MARKET, qty=100）|Matching Engine扫描当前VNM的Ask队列（卖单），按价格升序→时间升序选取最优对手方（最低价最早下单者），计算可成交数量（min(本单qty, 对手方qty)），生成Transaction记录|返回成交详情：`{symbol:"VNM", price:matched_price, qty:executed_qty, side:"BUY", status:"FILLED"}`；更新Book Order中对应Ask条目剩余量|
|2|用户提交Limit Sell Order（如：VNM, SELL, LIMIT, price=32500, qty=200）|Matching Engine检查当前VNM的Bid队列（买单）：若存在`bid_price ≥ 32500`的买单，则按价格降序→时间升序匹配；否则将本单插入Sell侧Order Book（按price降序、time升序排序）|若匹配成功：同上返回FILLED；若未匹配：返回`{status:"PENDING", order_id:"ORD_..."}`，订单进入Book等待|
|3|系统每秒刷新行情|聚合各股票最新Bid1/Bid2、Ask1/Ask2（共2档买卖盘），计算最新成交价（Last Price）、开盘价（首笔成交价）、收盘价（末笔成交价）、涨跌幅|推送JSON格式行情快照至前端，驱动Bảng giá渲染|

## 异常和边界
|场景|触发条件|预期处理|
|---|---|---|
|无对手方订单|Limit Order提交时，Book中无满足价格条件的反向订单（如Buy Limit 30000但最高Bid为29500）|订单进入Book Queue，状态设为`PENDING`；若至交易日结束仍未匹配，则自动解挂（Cancel），返还冻结资金/股份|
|跨日无成交|某股票当日无任何成交（即Book中无Matched Transaction）|开盘价 = 前一日收盘价；收盘价 = 前一日收盘价；参考价 = 前一日收盘价（保持链式稳定）|
|价格越界|Limit Order的price超出`refPrice×0.93 ~ refPrice×1.07`范围|拒绝接收订单，返回错误`ERR_PRICE_OUT_OF_RANGE`，不写入Book|
|市价单部分成交|Market Buy提交时，Ask队列总供给量 < 本单需求数量（如需买100股，但最低三档卖单合计仅80股）|分步匹配：先成交80股（按Ask1→Ask2→Ask3顺序），剩余20股状态为`PARTIALLY_FILLED`；后续若有新Ask进入，继续匹配直至完成或超时|

## 输入、输出和状态变化

**输入**：  
- Order对象：`{symbol, side("BUY"/"SELL"), type("MARKET"/"LIMIT"), price?(optional), quantity, timestamp}`  
- 全局状态：`refPrice[symbol]`（前日收盘价）、`trading_session_active`（时段开关）

**输出**：  
- Transaction对象：`{id, symbol, price, qty, side, time, matched_with_order_id}`  
- Order状态更新：`FILLED`/`PARTIALLY_FILLED`/`PENDING`/`CANCELLED`  
- Book Order结构变更：Ask/Bid队列节点增删改（按price-time priority重排序）

**状态变化**：  
- `Order`实体：`status`字段从`SUBMITTED`→`PENDING`/`FILLED`/`CANCELLED`；`filled_qty`累加；`remaining_qty`递减  
- `Book Order`：Bid队列（升序价格）/Ask队列（降序价格）动态插入、删除、数量更新；Top2 Bid/Ask值实时重算  
- `Stock State`：`last_price`, `open_price`, `close_price`, `change_percent` 四字段随每笔成交原子更新  

## 关联知识

**关联规则**：  
- 价格规则：`refPrice = previous_close`（HOSE规则，见原文P2）；`upper_limit = refPrice × 1.07`, `lower_limit = refPrice × 0.93`（项目特化，见原文P3⚠）  
- 匹配规则：Price-Time Priority（价格优先→时间优先），非Pro-Rata（见原文P4）  
- 订单生命周期：`PENDING`→`FILLED`/`CANCELLED`（末笔未匹配则自动Cancel，见原文P3）  

**关联流程**：  
- 订单流：User → Frontend → Order Gateway → Matching Engine → Transaction Log → Quote Feed → Frontend  
- 行情流：Matching Engine（每成交一笔）→ Quote Aggregator → WebSocket Broadcast → Bảng giá渲染（仅显示Bid1/Bid2/Ask1/Ask2，见原文P6⚠）  

**关联接口**：  
- `POST /api/orders`（订单提交）  
- `GET /api/quotes/{symbol}`（实时行情，返回top2 bid/ask）  
- `GET /api/orders/{id}`（订单状态查询）  
- `Websocket /stream/quotes`（全市场行情推送）
