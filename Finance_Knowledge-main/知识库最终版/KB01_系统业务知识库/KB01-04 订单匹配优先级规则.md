## 规则名称
价格-时间优先（Price-Time Priority）订单匹配引擎规则

## 规则目的
实现符合国际主流交易所标准的公平、透明、可预测的订单执行机制，确保价格发现过程反映真实供需关系；为教学提供可复现的匹配逻辑，支撑“supply-demand interactions”教育目标。

## 适用条件
- 系统处于开放交易时段（`tradingSessionService` 返回 `status === 'OPEN'`）；
- 提交的订单类型为 **Limit Order**（Buy/Sell）或 **Market Order**（Buy/Sell）；
- 匹配发生在同一股票（`stock_id`）的Order Book内。

## 规则内容
当一个新订单（New Order）进入某股票的Order Book时，系统应：
1. 若为**Market Buy Order**：从Ask队列（Sell Limit Orders）中，按**价格升序**（低价优先）、**时间升序**（先到先服务）扫描，匹配所有满足 `ask_price ≤ market_buy_price_implied` 的卖单，直至买方数量耗尽或卖单耗尽；
2. 若为**Market Sell Order**：从Bid队列（Buy Limit Orders）中，按**价格降序**（高价优先）、**时间升序**（先到先服务）扫描，匹配所有满足 `bid_price ≥ market_sell_price_implied` 的买单，直至卖方数量耗尽或买单耗尽；
3. 若为**Buy Limit Order**（price = P）：从Ask队列中，按**价格升序**扫描，匹配所有 `ask_price ≤ P` 的卖单；匹配顺序为：先匹配价格最低者，同价者匹配时间最早者；
4. 若为**Sell Limit Order**（price = P）：从Bid队列中，按**价格降序**扫描，匹配所有 `bid_price ≥ P` 的买单；匹配顺序为：先匹配价格最高者，同价者匹配时间最早者；
5. 若匹配产生部分成交（Partial Match），系统应将订单**原子性拆分**为：① 已匹配部分（立即结算）；② 未匹配部分（以原价格/时间戳加入对应队列）；
6. 所有匹配操作必须在**单一线程/事务内完成**，确保Order Book状态最终一致性。

## 处理结果
|情况|系统处理|返回结果|
|满足规则|执行匹配逻辑；更新Order Book；调用`orderSettlementService.js`更新用户余额/持仓；生成Transaction记录|HTTP 201 + `{ "status": "PARTIAL_MATCH", "matched_volume": 5, "remaining_volume": 4 }`|
|不满足规则|订单未匹配，完整加入对应队列（Bid或Ask）；Order Book状态更新|HTTP 201 + `{ "status": "ADDED_TO_BOOK", "book_position": "Bid_Queue_Top3" }`|

## 例外和边界
- **零价格/负价格**：系统禁止创建价格≤0的Limit Order（`orderValidationMiddleware`拦截）；Market Order隐含价格由匹配引擎动态推导，不存于订单本身；
- **同价同时间**：实际中因Node.js微秒级时间戳精度，同价同毫秒订单极罕见；若发生，按数据库插入顺序（`created_at`）二次排序；
- **队列为空**：Ask/Bid队列为空时，Market Order仍可提交（等待后续挂单），但不会触发任何匹配。

## 正面示例
- Ask队列存在：`(price=160, vol=5)`, `(price=162, vol=3)`；  
  新Buy Limit订单：`(price=170, vol=9)` → 匹配160×5，剩余4单位以170价入Bid队列。

## 反面示例
- Bid队列存在：`(price=155, vol=10)`；  
  新Sell Limit订单：`(price=150, vol=8)` → 无`bid_price ≥ 150`（155≥150成立，但155>150，故匹配）→ 实际应匹配；  
  *修正反例*：新Sell Limit `(price=145, vol=8)` → 无`bid_price ≥ 145`（155≥145成立）→ 仍匹配；  
  *真正反例*：Bid队列全为`(price=140, vol=5)`，新Sell Limit `(price=145, vol=8)` → 140 < 145 → 无匹配 → 全单入Ask队列。

## 模拟声明
本规则为**P2级模拟基准**。平台严格实现Price-Time Priority（非Pro-Rata），且**仅维护Buy/Sell两个独立队列**（未实现Iceberg/Hidden Orders等高级类型）。匹配粒度为“逐笔撮合”，非集合竞价（ATO/ATC），符合项目“continuous matching only”范围声明。此设计使学生可清晰观察“价高者得买、价低者得卖”的微观市场动力学。
