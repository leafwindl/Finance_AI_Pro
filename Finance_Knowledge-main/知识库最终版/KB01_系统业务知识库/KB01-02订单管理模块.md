## 模块名称  
Order Management Module（订单管理模块）  

## 模块职责  
**负责**：接收、校验、持久化、状态流转及生命周期管理用户提交的买卖订单；支持限价单/市价单基础类型；协同订单撮合引擎触发成交逻辑。  
**不负责**：订单撮合算法实现（由 `orderMatchingService.js` 独立承担）、资金冻结/解冻（由 `paymentService.js` 处理）、持仓更新（由 `holdingCRUDService.js` 执行）。  

## 主要功能  
| 功能 | 功能说明 | 触发入口 |  
|------|----------|----------|  
| 创建订单 | 校验用户权限、可用现金/持仓、股票存在性、价格合理性（如非负、非零），生成 `orderModel` 实例并持久化 | `POST /api/orders`（`orderController.js#createOrder`） |  
| 查询订单 | 支持按 `portfolio_id`、`stock_id`、`status`（PENDING/EXECUTED/CANCELLED）分页检索 | `GET /api/orders?portfolioId=...&status=...`（`orderController.js#getOrdersByPortfolio`） |  
| 取消订单 | 仅允许取消 `PENDING` 状态订单，更新状态并释放冻结资金/份额 | `PATCH /api/orders/:id/cancel`（`orderController.js#cancelOrder`） |  
| 订单状态同步 | 接收 `orderMatchingService` 的成交事件，自动更新订单状态为 `EXECUTED` 并关联 `transaction` | `orderController.js#handleMatchedOrder`（被 `orderMatchingService` 事件回调触发） |  

## 输入和输出  
**主要输入**：  
- HTTP 请求体：`{ portfolioId, stockId, orderType: 'BUY'|'SELL', quantity, price? }`（市价单 `price` 为空）  
- 上游中间件：`authenticationMiddleware`（验证 JWT）、`userValidationMiddleware`（检查用户激活状态）、`orderMiddleware`（校验 portfolio cash/holdings）  

**主要输出**：  
- 成功响应：`201 Created` + `{ orderId, status: 'PENDING', createdAt }`  
- 数据库写入：`orderModel` 记录（含 `status`, `filledQuantity`, `remainingQuantity`）  
- 事件广播：`order:created`（供 `orderMatchingService` 监听）  

## 上游和下游  
| 关系 | 系统/模块 | 交互内容 |  
|------|-----------|----------|  
| 上游 | User Management Module | 提供认证后的 `userId`、`role`（用于 RBAC 权限校验） |  
| 上游 | Portfolio Management Module | 提供 `portfolioId` 对应的 `cash_balance` 和 `holdings`（用于下单前资金/持仓校验） |  
| 下游 | Order Matching Service | 发送 `order:created` 事件，传递 `orderId`, `stockId`, `orderType`, `price`, `quantity` |  
| 下游 | Transaction Management Module | 接收 `order:executed` 事件，创建 `transactionModel` 记录 |  
| 下游 | Holding Management Module | 接收 `order:executed` 事件，调用 `holdingCRUDService.updateHolding()` 更新持仓 |  

## 主要异常  
- `400 Bad Request`: `price <= 0`（BUY 单）、`quantity <= 0`、`stockId` 不存在  
- `403 Forbidden`: 用户无权操作目标 `portfolioId`（跨账户下单）  
- `409 Conflict`: `PENDING` 订单余额不足（`cash_balance < price * quantity` for BUY）或持仓不足（`holding.quantity < quantity` for SELL）  
- `500 Internal Error`: 数据库写入失败（如唯一约束冲突）  

## 关联规则、流程和接口  
- **规则**：订单状态机严格遵循 `PENDING → EXECUTED/CANCELLED`，不可逆；`EXECUTED` 订单禁止修改。  
- **流程**：`orderController#createOrder` → `orderMiddleware#validateOrder` → `orderCRUDService.createOrder()` → `orderModel.save()` → 发布 `order:created` 事件。  
- **接口**：`orderRoutes.js` 定义 `/orders` 路由；`orderController.js` 实现 CRUD 方法；`orderCRUDService.js` 封装数据库操作。
