## 当前模块或功能  
Payment Gateway Integration（支付网关集成）—— 实现虚拟资金充值，位于 `services/paymentService.js`，对接 Sepay 第三方支付 API，完成 QR 码生成、交易核验与余额更新。  

## 依赖清单  
|依赖系统/模块|依赖内容|调用方向|必需/可选|  
|---|---|---|---|  
|`Sepay API`|`POST /v1/qr`（生成 QR）、`GET /v1/transaction/{ref}`（核验交易）|HTTP 同步调用|必需|  
|`PostgreSQL`|读取用户 `portfolios.cash_balance`；写入 `payment_transactions` 与更新 `portfolios.cash_balance`|同步调用|必需|  
|`Nginx`（反向代理）|对外暴露 `/api/payment/*` 路径，隐藏 Sepay API 密钥与内网地址|流量代理|必需|  
|`Cloudflare WAF`|过滤恶意请求（如 SQLi/XSS 注入到 `transaction_ref` 参数）|网络层防护|必需|  

## 正常调用顺序  
1. 用户点击“Add Fund” → 前端调用 `POST /api/payment/qr` →  
2. `paymentService.generateQR()` 调用 Sepay `/v1/qr` →  
3. Sepay 返回 QR URL 与 `payment_id` →  
4. 用户扫码支付 → Sepay 通知银行 → 银行回调 Sepay →  
5. 用户提交 `transaction_ref` → 前端调用 `POST /api/payment/verify` →  
6. `paymentService.verifyTransaction(ref)` 调用 Sepay `/v1/transaction/{ref}` →  
7. 核验成功后，更新 `portfolios.cash_balance` 并插入 `payment_transactions`。  

## 依赖不可用时的处理  
|异常|处理方式|是否重试|对用户/业务的影响|  
|---|---|---|---|  
|Sepay API 超时（>10s）|返回 `504 Gateway Timeout`，前端提示“支付通道繁忙，请稍后重试”|是（用户手动重试）|用户无法完成充值，但已生成 QR 仍有效（Sepay 侧时效 2h）|  
|Sepay 返回 `404 Transaction Not Found`|记录 `loggerUtil.warn`，返回 `400 Bad Request` + “交易号无效”|否|用户需确认银行转账是否完成，避免重复提交|  
|PostgreSQL 更新失败|事务回滚，返回 `500 Internal Error`，不扣减用户余额|否|资金零损失，用户可重新提交核验|  

## 数据一致性和超时要求  
- **强一致性**：Sepay 核验成功 ↔ PostgreSQL 余额更新 必须在同一事务内完成；  
- **超时阈值**：Sepay `/v1/transaction/{ref}` 调用 ≤ 8s（Sepay SLA）；  
- **幂等设计**：`transaction_ref` 为唯一索引，重复提交同一 ref 仅更新一次余额。  

## 建议测试场景  
- 【资金安全】模拟 Sepay 核验返回 `amount=0`，验证 `paymentService` 拒绝更新余额；  
- 【防重放】同一 `transaction_ref` 提交两次，验证第二次返回 `409 Conflict`；  
- 【网络分区】断开与 Sepay 的网络，验证前端正确展示降级提示而非白屏；  
- 【合规】检查 `payment_transactions` 表是否加密存储 `bank_account_last4`（文档未提，故标记为 `N/A`）。
