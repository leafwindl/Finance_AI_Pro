## 功能名称和目的
**功能名称**：Cloudflare Turnstile 人机验证  
**目的**：在用户关键操作（如登录）前，无缝验证其为真实人类而非自动化脚本，以抵御暴力破解、爬虫与垃圾注册；采用无感（Invisible）模式，在保障安全的同时最小化用户交互摩擦，替代侵入式reCAPTCHA。

## 使用角色或调用方
- **终端用户**：在登录表单中，Turnstile Widget 自动加载并后台验证。
- **前端应用**：`Login.jsx` 组件（React），负责动态加载Turnstile SDK并处理Token。
- **后端服务**：`authController.js`（或等效登录路由），负责验证Token有效性。

## 操作入口
- **前端入口**：登录页面（Navbar点击后弹出）加载Turnstile Widget。
- **后端入口**：`/api/login` 接口在生产环境（`NODE_ENV === 'production'`）下，强制校验 `cf-turnstile-response` Token。

## 前置条件
- 已在 [Cloudflare Dashboard](https://dash.cloudflare.com/) 的Turnstile页面创建应用，获取 `SITE_KEY`（前端）与 `TURNSTILE_SECRET_KEY`（后端）。
- `SITE_KEY` 已配置至前端环境变量 `VITE_SITE_KEY`；`TURNSTILE_SECRET_KEY` 已配置至后端 `.env`。
- 前端域名（`soictstock.io.vn`, `localhost`）已在Cloudflare Turnstile中白名单注册。

## 正常处理
|步骤|操作/输入|系统处理|输出|
|---|---|---|---|
|1|用户访问登录页 | 前端 `useEffect` 动态加载 `https://challenges.cloudflare.com/turnstile/v0/api.js`；调用 `turnstile.render()` 渲染Widget | 页面显示Turnstile徽标（Light主题），后台静默执行行为分析 |
|2|用户完成验证（显式或隐式） | Turnstile SDK 生成一次性Token，并通过 `callback(token)` 传入前端 | 前端 `setTurnstileToken(token)`，Token存入表单状态 |
|3|用户提交登录表单 | 前端将 `cf-turnstile-response: <token>` 作为请求头或请求体字段发送至 `/api/login` | 后端收到含Token的请求 |
|4|后端验证Token | 发起HTTPS POST至 `https://challenges.cloudflare.com/turnstile/v0/siteverify`，携带 `secret`（SECRET_KEY）与 `response`（Token） | Cloudflare返回JSON：`{ "success": true, "score": 0.9, "action": "login" }` |
|5|后端决策 | 若 `success === true` 且 `score > 0.5`（典型阈值），则继续执行密码验证流程；否则返回错误 | 登录流程继续，或返回CAPTCHA错误 |

## 异常和边界
|场景|触发条件|预期处理|
|---|---|---|
|**Token过期**| 用户长时间未提交，Turnstile Token失效（默认约2分钟） | `expired-callback` 触发，前端清空 `turnstileToken`；提交时因 `!turnstileToken` 抛出 `Please complete the CAPTCHA` 错误。 |
|**验证失败**| Cloudflare返回 `success: false`（如机器人行为评分过低） | 后端拒绝登录请求，返回统一错误，前端提示用户重试。 |
|**开发环境绕过**| `import.meta.env.MODE !== 'production'`（即本地开发） | 前端跳过Token检查（`if (!identifier || !password)` 仅校验必填字段），`turnstileToken` 非必填。 |

## 输入、输出和状态变化

**输入**：  
- 用户设备行为数据（鼠标移动、键盘敲击、触摸事件等）  
- Cloudflare Turnstile `SITE_KEY`（前端）与 `SECRET_KEY`（后端）  

**输出**：  
- 前端：一次性 `cf-turnstile-response` Token  
- 后端：Cloudflare `siteverify` API 的JSON响应（含 `success`, `score`, `action`）  

**状态变化**：  
- 用户会话状态：从“未通过人机验证”变为“已通过人机验证”，方可进入密码校验阶段。  
- 安全态势：有效阻断自动化脚本对 `/api/login` 接口的高频探测与爆破。  

## 关联知识

**关联规则**：  
- **Invisible模式**：无需用户点击复选框，通过分析用户自然交互行为（`mouse movement`, `keystrokes`）进行无感验证，原文称其为“implicitly solving”。  
- **Score-based决策**：不同于二元验证，Turnstile返回0.0~1.0的置信度分数，允许后端根据业务风险灵活设定阈值（如登录用0.7，支付用0.9）。  

**关联流程**：  
- 验证流：`Login Page → Load Turnstile SDK → Render Widget → User Interaction → Generate Token → Submit with Login → Backend Verify → Proceed/Reject`  

**关联接口**：  
- Frontend: `window.turnstile.render(element, { sitekey, theme, callback })`  
- Backend: `POST https://challenges.cloudflare.com/turnstile/v0/siteverify`
