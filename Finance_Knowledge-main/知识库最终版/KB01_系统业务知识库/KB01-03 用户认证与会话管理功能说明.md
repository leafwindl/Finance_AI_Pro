## 功能名称和目的  
**名称**：可信设备增强型多因素用户认证与会话生命周期管理（Trusted-Device Augmented MFA Authentication & Session Lifecycle Management）  
**目的**：  
- 提供符合 OWASP ASVS Level 2+ 要求的安全登录流程，抵御暴力破解、凭证填充、CSRF 及会话劫持；  
- 建立“用户-设备-会话”三维信任模型，通过设备指纹（`visitor_id`）与置信度评分（`confidence_score`）实现动态风险自适应认证；  
- 支持无感续期（Silent Renewal）与显式失效（Explicit Expiry），确保会话既可用又可控；  
- 为后续 RBAC（角色访问控制）、交易风控、审计溯源提供可信身份锚点。

## 前置条件  
| 条件类别 | 具体要求 | 验证方式 |  
|----------|----------|----------|  
| 数据前提 | 用户账户已激活（`Users.status = 'active'`）且未被锁定（`Users.locked_until IS NULL OR Users.locked_until < NOW()`） | `userValidationMiddleware.js` 查询 `userModel` |  
| 设备前提 | 前端已通过 `turnstileService.js` 完成 Cloudflare Turnstile 验证（返回有效 `cf-turnstile-response` token） | `roleBasedAccessControlMiddleware.js` 校验请求头 `X-CF-Turnstile-Token` |  
| 环境前提 | `remembered_deviceService` 已初始化并连接至 Redis（用于缓存设备会话状态） | `config/dbConnect.js` 加载时校验 Redis 连接健康度 |  
| 安全前提 | 密码强度满足 `passwordUtil.js` 的 zxcvbn v4.4 规则（≥8 字符，含大小写字母+数字+符号，熵值 ≥ 60 bit） | `userControllers.js` 在注册/改密时调用 `passwordUtil.validate()` |  

## 正常处理  
| 步骤 | 操作/输入 | 系统处理 | 输出 |  
|------|-----------|----------|------|  
| 1 | 用户提交 `username` + `password` + `cf-turnstile-token` | `authenticationMiddleware.js` 验证 Turnstile Token 有效性；`userControllers.js` 调用 `userAuthService.authenticate()` | 若失败：HTTP 401 + `{ error: "invalid_captcha" }`；若成功：进入步骤 2 |  
| 2 | 凭证校验通过，生成临时会话 ID（`temp_session_id`） | `userAuthService` 查询 `rememberedDeviceService.isTrustedDevice()`，传入 `req.ip` + `User-Agent` + `FingerprintJS hash` 生成 `visitor_id` | 返回 `is_trusted: true/false`，决定是否跳过 OTP |  
| 3 | 若 `is_trusted == false`：发送 OTP 至用户绑定邮箱/手机 | `otpService.js` 生成 6 位时效 OTP（5 分钟），加密存储至 `otpModel`，调用 `nodemailer` 发送 | HTTP 202 + `{ requires_otp: true, otp_sent_to: "email" }` |  
| 4 | 用户提交 OTP | `userControllers.js` 调用 `otpService.verify()`，校验时效性与次数限制（≤3 次/小时） | 若失败：HTTP 400 + `{ error: "otp_invalid_or_expired" }`；若成功：进入步骤 5 |  
| 5 | 生成 JWT Access Token（72h）与 Refresh Token（7d），写入 `remembered_devices` 表（含 `confidence_score` 计算） | `userAuthService.issueTokens()`：<br>• 计算 `confidence_score = 0.9 - (risk_factor * 0.3)`（risk_factor 来自 IP 地理异常、UA 变更、历史失败率）<br>• 插入 `remembered_devices` 表（`user_id`, `visitor_id`, `confidence_score`, `expires_at = NOW() + INTERVAL '7 days'`）<br>• 设置 HttpOnly Secure Cookie `refresh_token` | HTTP 200 + `{ access_token: "...", user: { id, username, role }, trusted_device: true/false }` |  
| 6 | 前端 `AuthContext.jsx` 持有 `access_token`，自动在后续请求中添加 `Authorization: Bearer <token>` | `authenticationMiddleware.js` 解析 JWT，验证签名与有效期；`roleBasedAccessControlMiddleware.js` 根据 `req.user.role` 控制路由访问 | 成功：透传至对应 controller；失败：HTTP 401/403 |  

## 异常和边界  
| 场景 | 触发条件 | 预期处理 |  
|------|----------|----------|  
| 暴力破解防护 | 同一 `username` 在 15 分钟内连续 5 次失败登录 | `userValidationMiddleware.js` 设置 `Users.locked_until = NOW() + INTERVAL '30 minutes'`，返回 HTTP 429 + `{ locked_until: "2024-05-20T10:30:00Z" }` |  
| 设备信任降级 | 同一 `visitor_id` 在 24 小时内 `confidence_score` 低于 0.4（如多次异地登录） | `rememberedDeviceService` 自动将 `expires_at` 缩短至 24 小时，并标记 `is_degraded = true`，下次登录强制 OTP |  
| Refresh Token 过期 | `refresh_token` Cookie 过期或被篡改 | `authenticationMiddleware.js` 拒绝刷新，清空客户端 Cookie，重定向至 `/login?reason=expired` |  
| 设备冲突 | 用户在新设备登录时勾选“信任此设备”，但数据库中已存在同 `user_id` + 同 `visitor_id` 记录 | `rememberedDeviceService.upsert()` 执行 `ON CONFLICT (user_id, visitor_id) DO UPDATE`，更新 `confidence_score` 与 `expires_at`，不报错 |  
| Turnstile 失效 | `cf-turnstile-token` 无效或已使用 | `roleBasedAccessControlMiddleware.js` 直接返回 HTTP 400 + `{ error: "captcha_verification_failed" }`，不进入认证逻辑 |  

## 输入、输出和状态变化  

**输入**：  
- `username`（string, required）  
- `password`（string, required, bcrypt-hashed in DB）  
- `cf-turnstile-token`（string, required, from frontend Turnstile widget）  
- `remember_device`（boolean, optional, default `false`）  
- `otp_code`（string, 6-digit, required only if `requires_otp == true`）  

**输出**：  
- HTTP Status Code（200, 202, 400, 401, 403, 429）  
- JSON Body（含 `access_token`, `user` profile, `trusted_device`, `requires_otp` 等字段）  
- HttpOnly Secure Cookie `refresh_token`（maxAge=7d）  
- Frontend `AuthContext` state update（`isAuthenticated`, `user`, `loading`）  

**状态变化**：  
- `Users.failed_login_count` 自增（失败时），成功后重置为 0  
- `remembered_devices` 表新增或更新一行（`user_id`, `visitor_id`, `confidence_score`, `expires_at`）  
- `otpModel` 中对应 `username` 的 OTP 记录被标记为 `used = true`  
- Redis 缓存中 `session:<temp_session_id>` 被删除，`device:<visitor_id>:score` 被更新  

## 关联知识  

**关联规则**：  
- **信任阈值规则**：`confidence_score ≥ 0.7` → 免 OTP；`0.4 ≤ score < 0.7` → 首次登录需 OTP，后续免；`score < 0.4` → 每次均需 OTP + Turnstile  
- **会话继承规则**：Refresh Token 刷新时，新 Access Token 继承原会话的 `confidence_score`，不重新计算设备风险  
- **级联删除规则**：`DELETE FROM Users WHERE user_id = X` → 自动触发 `remembered_devices` 表中 `ON DELETE CASCADE` 删除所有关联设备记录  

**关联流程**：  
- 用户注册流程（`POST /api/v1/auth/register`）→ 初始化 `userModel` + `otpModel` + `rememberedDeviceService.initForNewUser()`  
- 密码重置流程（`POST /api/v1/auth/forgot-password`）→ 生成一次性 reset token，**不重置设备信任状态**  
- 管理员强制登出（`PATCH /api/v1/admin/users/:id/revoke-sessions`）→ 调用 `userCRUDService.revokeAllSessions()`，删除 `remembered_devices` + Redis session keys  

**关联接口**：  
- `POST /api/v1/auth/login`（`userRoutes.js`）  
- `POST /api/v1/auth/otp/verify`（`userRoutes.js`）  
- `POST /api/v1/auth/refresh`（`userRoutes.js`）  
- `DELETE /api/v1/auth/logout`（`userRoutes.js`）  
- `GET /api/v1/user/profile`（`userRoutes.js`，受 `authenticationMiddleware` 保护）
