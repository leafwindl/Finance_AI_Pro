## 模块名称  
用户管理模块（User Management Module）

## 模块职责  
**负责：**  
- 全生命周期用户实体管理：包括注册（含邮箱验证）、登录（含多因素认证MFA）、密码重置、个人信息维护（非敏感字段）、账户状态（active/inactive）控制；  
- 基于角色的访问控制（RBAC）实施：区分 `user` 与 `admin` 角色，赋予 `admin` 对任意用户执行软删除（soft-delete）权限；  
- 安全上下文构建：集成 OTP 动态口令、可信设备记忆（remembered_devices）、Cloudflare Turnstile 人机验证、JWT 令牌签发与校验；  
- 用户会话与状态持久化：通过 `userModel.js` 与数据库交互，确保数据一致性与事务完整性。

**不负责：**  
- 交易行为本身（如下单、撮合、结算）—— 由 `Order`, `TradingSession`, `Transaction` 等模块承担；  
- 投资组合资产计算（cash_balance, total_value）—— 由 `PortfolioController` 及其服务层处理；  
- 市场数据获取与更新（stock prices, news）—— 由 `StockPriceController` 和 `seedStockPrice/` 工具链驱动；  
- 前端UI渲染与路由跳转 —— 属于 `frontend/src/pages/` 与 `context/AuthContext.jsx` 职责范围。

## 主要功能  

| 功能 | 功能说明 | 触发入口 |
|------|----------|----------|
| **用户注册** | 收集 username/email/password，校验唯一性与强度，发送验证邮件，创建 `userModel` 实例并初始化 `portfolioModel`（含100,000虚拟资金），调用 `otpService` 生成初始OTP种子 | `POST /api/users/register`（前端 `RegisterForm.jsx` 提交） |
| **用户登录** | 验证凭据，检查账户状态，执行 `roleBasedAccessControlMiddleware`，生成JWT，设置HttpOnly Cookie，并记录可信设备（`rememberedDeviceService`） | `POST /api/users/login`（前端 `LoginForm.jsx` 提交） |
| **OTP二次验证** | 在登录或敏感操作时，比对用户输入的6位动态码与 `otpModel` 中存储的加密密钥生成的当前有效码 | `POST /api/users/verify-otp`（前端 `OtpForm.jsx` 提交） |
| **管理员用户删除** | `admin` 角色调用软删除接口，仅将 `Users.updated_at` 更新并标记 `is_deleted = true`，不物理删除，保障 `Portfolios`/`Transactions` 外键完整性 | `DELETE /api/admin/users/:userId`（Admin页面调用 `userRoutes.js`） |
| **密码找回** | 通过邮箱发送重置链接（含JWT token），校验token时效性与签名，允许用户设置新密码（经 `passwordUtil.js` 加密） | `POST /api/users/forgot-password` → `PUT /api/users/reset-password` |

## 输入和输出  

**主要输入：**  
- HTTP 请求体（JSON）：`{ "username", "email", "password", "otp_code", "new_password", "reference_number" }`  
- HTTP 请求头：`Authorization: Bearer <JWT>`、`X-Visitor-ID`（用于设备指纹识别）  
- 数据库查询参数：`user_id`, `email`, `username`, `visitor_id`  

**主要输出：**  
- HTTP 响应体（JSON）：成功时返回 `user` 对象（不含密码哈希）、JWT token、`portfolio_id`；失败时返回标准化错误码（如 `400 Bad Request`, `401 Unauthorized`, `403 Forbidden`）  
- 数据库写入：`users`, `portfolios`, `otpModel`, `remembered_devices` 表的新增/更新记录  
- Cookie：`auth_token`（HttpOnly, Secure, SameSite=Strict）  

## 上游和下游  

| 关系 | 系统/模块 | 交互内容 |
|------|-----------|----------|
| **上游** | 前端 `AuthContext.jsx` | 提供登录态、用户信息、JWT token；触发 `api/user.js` 的所有请求；接收 `RoleProtectedRoute.jsx` 的角色鉴权结果 |
| **下游** | `PortfolioCRUDService.js` | 创建新用户时，调用 `portfolioCRUDService.createDefaultPortfolio(userId)` 初始化虚拟资金账户 |
| **下游** | `Security/otpService.js` | 注册/登录流程中，调用 `generateSecret()` 与 `verifyToken()` 实现TOTP逻辑 |
| **下游** | `Security/rememberedDeviceService.js` | 登录成功后，基于 `visitor_id` 与 `confidence_score` 写入 `remembered_devices` 表 |
| **下游** | `Security/turnstileService.js` | 在注册/登录端点前置调用，验证 `cf-turnstile-response` 头部，拦截自动化脚本 |

## 主要异常  

- **凭证泄露风险**：若 `passwordUtil.js` 未使用 bcrypt salt rounds ≥ 12，或 JWT secret key 硬编码于 `passportConfig.js`，将导致横向越权；  
- **OTP 同步失效**：客户端时间偏差 > 30s 时，`otpService.verifyToken()` 返回 false，需提示用户校准设备时间；  
- **软删除级联断裂**：`admin` 删除用户后，若 `Portfolios.user_id` 未设 `ON DELETE SET NULL`，将导致 `Holdings.portfolio_id` 外键引用失效；  
- **设备信任降级**：`remembered_deviceService` 中 `expires_at` 过期后未自动清理，可能积累无效设备记录，影响 `confidence_score` 准确性；  
- **JWT 令牌劫持**：未强制 `HttpOnly` + `Secure` Cookie 属性，或前端 `localStorage` 存储 token，易受 XSS 攻击。

## 关联规则、流程和接口  

- **核心规则**：  
  - 所有用户操作必须通过 `authenticationMiddleware.js` 校验 JWT 有效性；  
  - `admin` 权限需经 `roleBasedAccessControlMiddleware.js` 显式校验 `req.user.role === 'admin'`；  
  - 密码重置链接有效期严格为 15 分钟（`constants.js` 中 `RESET_TOKEN_EXPIRY = '15m'`）；  
  - `remembered_devices` 表 `UNIQUE(user_id, visitor_id)` 约束防止重复设备注册。  
- **关键流程**：  
  `Register → validate → hash password → create user → init portfolio → send email → store OTP seed`  
  `Login → verify credentials → check role → generate JWT → record device → set cookie`  
- **对外接口**：  
  - RESTful API：`/api/users/register`, `/api/users/login`, `/api/users/verify-otp`, `/api/admin/users/:id`  
  - 内部服务接口：`userCRUDService.createUser()`, `userAuthService.login()`, `otpService.generateSecret()`
