## 当前模块或功能  
Authentication & Authorization Stack（认证鉴权栈）—— 包含 JWT 令牌签发/校验、Google OAuth2、RBAC 权限控制，核心文件：`middleware/authenticationMiddleware.js`, `passportConfig.js`, `roleBasedAccessControlMiddleware.js`。  

## 依赖清单  
|依赖系统/模块|依赖内容|调用方向|必需/可选|  
|---|---|---|---|  
|`JWT (access/refresh tokens)`|`jwtUtil.js` 生成/验证 token；`setCookieUtil.js` 写入 HttpOnly Cookie|同步调用|必需|  
|`Google OAuth2 API`|`passport-google-oauth20` 调用 `/token`, `/userinfo` 端点|HTTP 同步调用|可选（仅 Google 登录路径）|  
|`PostgreSQL`|读取 `users` 表验证凭据（`userCRUDService.js`）；读取 `remembered_devices` 表校验设备指纹|同步调用|必需|  
|`Cloudflare Turnstile`|前端渲染 widget + 后端 `turnstileService.js` 验证 `cf-turnstile-response`|HTTP 同步调用|必需（注册/登录/密码重置）|  

## 正常调用顺序  
1. 用户提交登录表单 →  
2. `userValidationMiddleware` 校验邮箱/密码格式 →  
3. `turnstileService.verify()` 调用 Cloudflare API →  
4. `userCRUDService.findByEmail()` 查询 PostgreSQL →  
5. `bcrypt.compare()` 校验密码 →  
6. `jwtUtil.signAccessToken()` 生成 token →  
7. `setCookieUtil.setAuthCookies()` 写入 HttpOnly Cookie →  
8. （Google 登录路径）`passport.authenticate('google')` 重定向 → Google → 回调 `/auth/google/callback` → `passportConfig` 处理 `userinfo`。  

## 依赖不可用时的处理  
|异常|处理方式|是否重试|对用户/业务的影响|  
|---|---|---|---|  
|Cloudflare Turnstile 验证失败|返回 `400 Bad Request` + “验证码验证失败”|是（前端刷新 widget）|阻止暴力破解，但增加用户操作步骤|  
|PostgreSQL 查询超时|返回 `503 Service Unavailable`|否|所有登录/注册失败，但静态页面（Home/Tutorial）仍可访问|  
|Google OAuth2 临时不可用|禁用 Google 登录按钮，显示“第三方登录暂不可用”|否|仅影响 Google 用户，本地账号不受影响|  

## 数据一致性和超时要求  
- **强一致性**：JWT `sub`（user_id）必须与 PostgreSQL `users.user_id` 严格一致；  
- **超时阈值**：Access Token 1min（测试环境），Refresh Token 7d；Turnstile 验证 ≤ 2s；  
- **安全约束**：HttpOnly Cookie + SameSite=Strict + Secure（生产环境强制 HTTPS）。  

## 建议测试场景  
- 【凭证泄露】抓包检查 `Set-Cookie` 是否包含 `HttpOnly; Secure; SameSite=Strict`；  
- 【越权】普通用户修改 `req.user.role='admin'` 后访问 `/admin`，验证 `roleBasedAccessControlMiddleware` 返回 403；  
- 【Token 伪造】用无效签名 JWT 访问 `/api/portfolio`，验证 `authenticationMiddleware` 拒绝；  
- 【设备绑定】同一账号在新设备登录，验证 `remembered_devices` 表新增记录且 `is_trusted=false`。
