## 模块名称  
Leaderboard Module（排行榜模块）  

## 模块职责  
**负责**：基于用户投资组合的历史绩效（`total_value` 增长率）进行排名；提供实时/日榜/周榜多维度榜单。  
**不负责**：绩效计算底层逻辑（由 `Portfolio Management Module` 提供 `total_value`）、用户身份管理（由 `User Management Module` 保障）、数据可视化（由 `Frontend` 渲染）。  

## 主要功能  
| 功能 | 功能说明 | 触发入口 |  
|------|----------|----------|  
| 计算用户绩效 | `returnRate = (current_total_value - initial_cash_balance) / initial_cash_balance`，`initial_cash_balance = 100000.00` | `leaderboardService.calculateReturnRate()`（定时任务或 API 调用） |  
| 生成排行榜 | 按 `returnRate` 降序排列所有活跃用户（`portfolio.total_value > 0`），返回 Top N | `GET /api/leaderboard?top=10&type=daily`（`leaderboardController.js#getLeaderboard`） |  
| 缓存排行榜 | 使用 Redis 缓存 `daily_leaderboard`、`weekly_leaderboard` 键，TTL 1h，避免高频 DB 查询 | `leaderboardService.cacheLeaderboard()`（在 `getLeaderboard` 中调用） |  

## 输入和输出  
**主要输入**：  
- `type`: `daily`/`weekly`（决定时间窗口，当前实现为全历史，未来可扩展）  
- `top`: 返回条目数（默认 10）  

**主要输出**：  
- 响应体：`{ rank, userId, username, returnRate, totalValue, updatedAt }`（Top N 用户）  
- Redis 缓存：`daily_leaderboard` → JSON 数组  

## 上游和下游  
| 关系 | 系统/模块 | 交互内容 |  
|------|-----------|----------|  
| 上游 | Portfolio Management Module | 提供 `portfolio.total_value` 和 `portfolio.cash_balance`（初始资金） |  
| 上游 | User Management Module | 提供 `username`（通过 `userModel.findById(userId)`） |  
| 下游 | Frontend Leaderboard Page | `GET /api/leaderboard` 获取数据渲染榜单 |  

## 主要异常  
- `503 Service Unavailable`: Redis 连接失败，降级为直查数据库（性能下降）  
- `500 Internal Error`: `returnRate` 计算除零（`initial_cash_balance = 0`，理论上不可能，因 `initUserUtil` 设为 `100000.00`）  

## 关联规则、流程和接口  
- **规则**：排行榜基于 `returnRate`（非绝对收益），鼓励相对表现；`userId` 与 `Users` 表 `1-1` 关联（文档中 `Users ↔ Leaderboard` 明确）。  
- **流程**：`leaderboardController#getLeaderboard()` → `leaderboardService.getFromCacheOrDB()` → `portfolioCRUDService.getAllPortfolios()` → `calculateReturnRate()` → `cacheLeaderboard()` → 返回。  
- **接口**：`leaderboardRoutes.js`（需补充，当前文档未显式列出但 Use Case 明确要求）；`leaderboardService.js`（隐含于 `services/` 目录结构，对应 `Leaderboard` Use Case）；`Users` & `Portfolios` 表关联。
