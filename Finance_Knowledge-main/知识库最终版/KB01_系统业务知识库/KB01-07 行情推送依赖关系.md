## 当前模块或功能  
Real-time Market Data Feed（实时行情推送）—— 通过 Server-Sent Events (SSE) 向前端推送股价、订单簿、成交信息，由 `ItemStatusActionSSE` 实现，位于 `middleware/sseMiddleware.js` 及相关控制器。  

## 依赖清单  
|依赖系统/模块|依赖内容|调用方向|必需/可选|  
|---|---|---|---|  
|`PostgreSQL`|监听 `stock_prices`、`orders`、`transactions` 表变更（通过 `LISTEN/NOTIFY` 或轮询）|数据源|必需|  
|`Node.js Event Loop`|SSE 连接维持长连接，依赖 `res.write()` 不阻塞主线程|运行时|必需|  
|`Nginx`|配置 `proxy_buffering off`、`proxy_cache off`、`keepalive_timeout 75s` 以支持 SSE 长连接|反向代理|必需|  
|`Frontend EventSource API`|浏览器端 `new EventSource('/api/sse')` 建立连接并处理 `message` 事件|客户端|必需|  

## 正常调用顺序  
1. 用户访问 `/trade` 页面 → 前端初始化 `EventSource('/api/sse')` →  
2. 后端 `sseMiddleware` 创建持久化 HTTP 连接（`res.writeHead(200, {...})`）→  
3. 后端启动定时任务（`setInterval`）或数据库 `NOTIFY` 监听 →  
4. 当 `stock_prices` 更新时，后端 `res.write("data: {...}\n\n")` 推送 JSON →  
5. 前端 `EventSource.onmessage` 解析并更新 React state（`useEffect` + `useState`）。  

## 依赖不可用时的处理  
|异常|处理方式|是否重试|对用户/业务的影响|  
|---|---|---|---|  
|PostgreSQL `NOTIFY` 失效|降级为 1s 轮询 `SELECT * FROM stock_prices WHERE updated_at > last_check`|是（自动）|行情延迟 ≤ 1s，无数据丢失|  
|Node.js Event Loop 阻塞|SSE 连接超时断开，前端 `onerror` 自动重连（`EventSource` 内置）|是（浏览器自动）|短暂黑屏（≤ 3s），随后恢复推送|  
|Nginx 关闭 `keepalive`|连接立即断开，前端触发 `reconnect`，但频繁重连增加服务器压力|是（前端控制）|用户体验卡顿，需 Nginx 配置审计|  

## 数据一致性和超时要求  
- **最终一致性**：SSE 推送延迟 ≤ 500ms（从 DB 更新到前端渲染）；  
- **超时阈值**：Nginx `keepalive_timeout` ≥ 75s；前端 `EventSource` `retry` 默认 3000ms；  
- **消息去重**：后端为每条消息添加 `id` 字段，前端 `EventSource` 自动处理重复 ID。  

## 建议测试场景  
- 【高并发】1000+ 用户同时连接 SSE，验证 Node.js `Event Loop` 无明显延迟（`process.hrtime()` 监控）；  
- 【断网恢复】前端断网 30s 后重连，验证 `lastEventId` 恢复续传（非全量重推）；  
- 【数据完整性】对比 SSE 推送的 `price` 与 PostgreSQL `stock_prices.last_price`，误差为 0；  
- 【资源泄漏】长时间运行（24h），监控 Node.js `activeHandles` 是否稳定。
