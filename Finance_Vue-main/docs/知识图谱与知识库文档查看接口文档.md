# 知识图谱与知识库文档查看接口文档

> 版本：v0.1  
> 状态：**待后端实现，真实联调阻塞；前端已通过 mock 验收（30/30）**  
> 调用方向：前端 → `Finance_AI_FASTAPI` Gateway

---

## 1: 需求以及在哪触发

**需求**：在前端展示知识库与文档的关系图；选择知识库后查看文档列表；选择文档后查看 Markdown 正文，并展开该文档的分块、实体与实体关系。

**触发位置**：登录后左侧边栏「知识图谱」，路由 `/knowledge-graph`。

**通用约定**：

- 浏览器只访问 Gateway，不直连知识库服务、Neo4j、PostgreSQL 或 Elasticsearch；
- 所有请求需要登录 Session Cookie，前端使用 `credentials: 'include'`；
- 路径参数由前端执行 URL 编码；
- 后端必须基于当前用户校验知识库及文档访问权限，不能只相信 URL 中的 `kbCode/docId`；
- 空知识库或空图谱返回 HTTP 200 与空数组；
- 当前仓库 Gateway 尚未实现以下 4 个 GET 路由，本文件是前后端对接契约，不代表已联调。

## 2: 接口一——获取知识图谱

```text
{
  1: 接口的路径:        GET /api/v1/knowledge/graph
  2: 接口的位置:        Finance_AI_FASTAPI（Gateway，前端唯一入口；
                        由 Gateway 内部查询知识库图谱数据）
  3: 发送接口方式:      GET（需登录 Session Cookie）
  4: 如果是post请说出传入参数:
       非 POST，无请求体
}
```

成功（HTTP 200）：

```json
{
  "nodes": [
    {
      "id": "kb:KB01",
      "type": "kb",
      "kb_code": "KB01",
      "label": "系统业务知识库",
      "count": 12
    },
    {
      "id": "doc:doc_x",
      "type": "doc",
      "doc_id": "doc_x",
      "kb_code": "KB01",
      "label": "需求说明",
      "source_file": "需求说明.md",
      "chunk_count": 8
    }
  ],
  "links": [
    {
      "source": "kb:KB01",
      "target": "doc:doc_x",
      "type": "CONTAINS"
    }
  ]
}
```

字段要求：

- `nodes[].id`：全图唯一、稳定的节点 ID；
- `nodes[].type`：基础图只包含 `kb`、`doc`；
- KB 节点必须提供 `kb_code / label / count`；
- 文档节点必须提供 `doc_id / kb_code / label`，建议同时返回 `source_file / chunk_count`；
- `links[].source/target` 必须是节点 ID 字符串，不能返回对象；
- KB 到文档关系类型为 `CONTAINS`。

## 3: 接口二——获取某知识库的文档列表

```text
{
  1: 接口的路径:        GET /api/v1/knowledge/kbs/{kbCode}/documents
  2: 接口的位置:        Finance_AI_FASTAPI（Gateway，前端唯一入口；
                        由 Gateway 内部查询指定知识库的文档）
  3: 发送接口方式:      GET（需登录 Session Cookie）
  4: 如果是post请说出传入参数:
       非 POST；路径参数 kbCode 为知识库编码（必填）
}
```

成功（HTTP 200）：

```json
{
  "documents": [
    {
      "doc_id": "doc_x",
      "title": "需求说明",
      "kb_code": "KB01",
      "source_file": "需求说明.md",
      "chunk_count": 8
    }
  ]
}
```

约定：

- `documents` 始终为数组；空知识库返回 `{"documents": []}`；
- `doc_id` 必须与全图、正文、子图接口使用同一个 ID；
- 每个文档的 `kb_code` 应与请求路径中的 `kbCode` 一致。

---

## 4: 接口三——获取文档 Markdown 正文

```text
{
  1: 接口的路径:        GET /api/v1/knowledge/documents/{docId}/content
  2: 接口的位置:        Finance_AI_FASTAPI（Gateway，前端唯一入口；
                        由 Gateway 内部查询文档元数据及正文）
  3: 发送接口方式:      GET（需登录 Session Cookie）
  4: 如果是post请说出传入参数:
       非 POST；路径参数 docId 为文档 ID（必填）
}
```

成功（HTTP 200）：

```json
{
  "doc_id": "doc_x",
  "title": "需求说明",
  "kb_code": "KB01",
  "source_file": "需求说明.md",
  "chunk_count": 8,
  "chars": 12543,
  "content_markdown": "# 需求说明\n\n正文……"
}
```

约定：

- `content_markdown` 始终为字符串；空文档返回空字符串，不返回 `null`；
- `chars`、`chunk_count` 为非负整数；
- 不得静默截断正文。如需要分页或截断，应另行增加明确字段和接口版本。

## 5: 接口四——获取文档分块与实体子图

```text
{
  1: 接口的路径:        GET /api/v1/knowledge/documents/{docId}/subgraph
  2: 接口的位置:        Finance_AI_FASTAPI（Gateway，前端唯一入口；
                        由 Gateway 内部查询文档分块、实体与关系）
  3: 发送接口方式:      GET（需登录 Session Cookie）
  4: 如果是post请说出传入参数:
       非 POST；路径参数 docId 为文档 ID（必填）
}
```

成功（HTTP 200）：

```json
{
  "nodes": [
    {
      "id": "chunk:doc_x:0",
      "type": "chunk",
      "doc_id": "doc_x",
      "kb_code": "KB01",
      "label": "第 1 块",
      "text": "分块正文"
    },
    {
      "id": "entity:session",
      "type": "entity",
      "kb_code": "KB01",
      "name": "用户会话",
      "entity_type": "MODULE",
      "description": "实体描述"
    }
  ],
  "links": [
    {
      "source": "doc:doc_x",
      "target": "chunk:doc_x:0",
      "type": "PART_OF"
    },
    {
      "source": "chunk:doc_x:0",
      "target": "entity:session",
      "type": "HAS_ENTITY"
    },
    {
      "source": "entity:session",
      "target": "entity:permission",
      "type": "RELATED"
    }
  ]
}
```

约定：

- 子图可不重复返回基础图中的文档节点，但关系端点必须使用基础图文档节点的 `id`；
- 所有子图节点必须包含 `kb_code`，供前端聚焦过滤；
- 节点 ID 全局唯一、稳定；
- 支持关系类型 `PART_OF / HAS_ENTITY / RELATED`；
- `entity_type` 为开放字符串；后端增加新类型时前端使用默认样式。

## 6: 错误约定

推荐状态码：

| HTTP | 场景 |
|---|---|
| 401 | 未登录或 Session 失效 |
| 403 | 当前用户无权访问该知识库或文档 |
| 404 | 知识库或文档不存在 |
| 422 | 路径参数格式错误 |
| 503 | 知识库/图谱上游服务不可用 |
| 504 | 上游请求超时 |

失败响应沿用现有格式：

```json
{ "detail": "错误原因" }
```

也兼容 Gateway 统一错误结构：

```json
{
  "error": {
    "code": "knowledge_graph_unavailable",
    "message": "知识图谱服务当前不可用",
    "retryable": true
  }
}
```

后端不得向浏览器返回数据库地址、Neo4j 凭证、内部启动命令或完整异常堆栈。

## 7: 联调验收条件

- 4 个 GET 接口均由 Gateway 提供并执行 Session/用户权限校验；
- 浏览器 Network 中只有 `/api/v1/knowledge/*`，不出现 8002、7687、9200 或数据库端口；
- 全图、列表、正文、子图中的 `doc_id` 与节点 ID 对应一致；
- 新文档通过 `POST /api/v1/knowledge/upload` 入库后，在约定刷新周期内能出现在列表和图谱中；
- 空态、无权限、服务不可用、超时场景返回上述约定结构。
