## 0. 前端"输入需求"能力：原本为什么不行、现在为什么可以

### 原本（新版前端整合后、改动前）为什么"不能输入需求"

**关键真相：不是完全没有输入能力，而是入口太隐蔽 + 主界面无入口**。

| 层面 | 原本状态 | 原因（代码事实） |
|---|---|---|
| ChatView 本身 | ✅ **有输入框**（`ChatComposer.vue` 的 `el-input type=textarea`，placeholder"输入你的问题，Enter 发送"） | 这是对话页通用输入，一直存在 |
| ChatView 自动发起 | ✅ **已支持** `route.query.q` → `handleSend` 自动发送（L76-86 / L118-127） | 既有实现，跳转带 `q` 参数就会自动发起 |
| **主界面 Dashboard** | ❌ **无任何需求输入入口**——只有 10 张固定需求卡片（r1~r10，硬编码示例需求）+ 已有会话卡片 | `DashboardView.vue` 的欢迎区只有标题和说明文字，没有任何输入框/按钮/弹窗 |
| 侧边栏"需求流程" | ⚠️ 可点进 ChatView 但**入口不显眼**，业务人员不知道 | 只是导航链接 |

**结论**：业务人员从主界面**没有"输入自己的需求"的入口**——要么点固定的示例卡片（r1~r10，内容写死，不是用户自己的需求），要么手动改 URL 进 `/chat/requirement-pre-review` 再粘贴输入。对"全流程自由输入需求"来说等于"不能输入"。

### 现在（改动后）为什么可以

**改了什么（`Finance_AI_Vue/src/views/DashboardView.vue`）**：

```
欢迎区新增"新建需求"按钮 + 弹窗
  │  openNewReqDialog()         ← 打开弹窗（需求名称可选 + 需求描述 textarea）
  │  submitNewRequirement()     ← 提交
  ▼
router.push({
  path: '/chat/requirement-pre-review',
  query: { q: <需求文本>, title: <名称或前100字>, pid: `custom_${Date.now()}` }
})
  ▼
ChatView 读到 route.query.q（已有逻辑 L76-86）
  ▼
handleSend({ text: q }) 自动发送 → agent1 预评审自动发起
```

**为什么能通**：**复用了既有的 `q` 参数自动发送机制**（ChatView L76-86）——只补了"主界面入口"（按钮+弹窗+跳转带 q），后面的自动发起是现成能力。这正是改动小的原因（DashboardView 一个文件）。

### 配套：后端已具备的能力（不用改）

- agent1 预评审：Gateway `/api/v1/chat`（agent_id=requirement-pre-review）SSE 流式 + 审批 → 已是现成
- 所以"新建需求 → 自动预评审"整条链路 = 前端补入口 + 复用现成机制，**后端零改动**

### 一句话总结

- **原本不行**：主界面没有任何需求输入入口（只有固定卡片），业务人员无法输入自己的需求
- **现在可以**：Dashboard 加"新建需求"按钮 + 弹窗 → 跳转带 `q` → 复用 ChatView 现成的 `q` 自动发起机制 → agent1 自动跑
