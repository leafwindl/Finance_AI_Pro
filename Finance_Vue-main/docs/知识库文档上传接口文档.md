# 知识库文档上传接口文档

> 前端 → 后端（Gateway），对接知识库入库功能。
> 版本：v2（自动分类）。  
> 状态：**后端已实现（`Finance_AI_FASTAPI/app/knowledge_gateway/kb_ingest.py` 已注册 upload + tasks），前端已按 v2 改造并通过 mock 验收；真实联调待 Gateway 启动后复测。**

---

## 1: 需求以及在哪触发

**需求**：用户将证券类文档（需求说明、测试用例、规范等）上传到知识库，供智能体后续检索使用。

**触发位置**：主界面「需求流程」面板与「测试用例流程」面板下方，一个合并的长方形拖拽框。用户把文件拖入框中（或点击框选择文件），即触发上传入库。

**交互（v2 异步任务）**：

- 前端默认**不传 kb_code → 后台按块全自动分类**（V2，推荐）；也可在下拉框手动指定 `KB01~KB06`，整篇归入指定库（V1 兼容）；
- 提交后由 `POST /knowledge/upload` 立即返回任务 ID（HTTP 202），前端轮询 `GET /knowledge/tasks/{taskId}` 直到终态；
- 完成后展示块级入库结果（总块数 + 各知识库分布）；失败展示后端错误信息；
- 单文件 ≤10MB，支持 `.md / .txt / .pdf / .docx`。

---

## 2: 接口一——提交入库任务

```
{
  1: 接口的路径:        POST /api/v1/knowledge/upload
  2: 接口的位置:        Finance_AI_FASTAPI（Gateway，端口 8000，前端唯一入口；
                        由 Gateway 内部转调分类服务与知识库服务 8002 完成解析、分类与入库）
  3: 发送接口方式:      POST（multipart/form-data，需登录 Session Cookie）
  4: 如果是post请说出传入参数:
       file     文件本体（必填，字段名 file；.md/.txt/.pdf/.docx，单文件 ≤10MB）
       kb_code  知识库编码（可选，KB01~KB06）；不传或空 → 后台自动分类；
                传非 KB01~KB06 → 400
}
```

提交成功（HTTP **202**）：

```json
{
  "task_id": "kb_1a2b3c4d5e6f",
  "file_id": "file_xxx",
  "filename": "需求说明.md",
  "status": "processing"
}
```

提交失败（HTTP 4xx）：沿用 `{ "detail": "错误原因" }` 或 `{ "error": { "code", "message", "retryable" } }`（如 `invalid_kb_code`、`unsupported_file_type`、`file_too_large`、`empty_file`）。

## 3: 接口二——查询入库任务状态

```
{
  1: 接口的路径:        GET /api/v1/knowledge/tasks/{taskId}
  2: 接口的位置:        Finance_AI_FASTAPI（Gateway，前端唯一入口）
  3: 发送接口方式:      GET（需登录 Session Cookie；仅本人任务可查）
  4: 如果是post请说出传入参数:
       非 POST；路径参数 taskId 为上传接口返回的 task_id（必填）
}
```

未完成（HTTP 200，`status` 为 `processing`/`pending`）：

```json
{
  "task_id": "kb_1a2b3c4d5e6f",
  "filename": "需求说明.md",
  "status": "processing",
  "progress": { "stage": "解析", "percent": 30 },
  "created_at": "2026-08-20T10:00:00Z"
}
```

完成（HTTP 200，`status` 为 `completed`，新增 `result`）：

```json
{
  "task_id": "kb_1a2b3c4d5e6f",
  "filename": "需求说明.md",
  "status": "completed",
  "progress": { "stage": "done", "percent": 100 },
  "result": {
    "kb_distribution": { "KB01": 2, "KB04": 1 },
    "total_chunks": 3,
    "blocks": [
      { "heading": "第一章 总则", "kb_code": "KB01", "doc_id": "doc_xxx" }
    ],
    "kb_code": "KB01",
    "doc_id": "doc_xxx"
  }
}
```

失败（HTTP 200，`status` 为 `failed`，新增 `error`）：

```json
{
  "task_id": "kb_1a2b3c4d5e6f",
  "filename": "需求说明.md",
  "status": "failed",
  "error": { "code": "ingest_failed", "message": "没有可入库的知识块（全部 OUT_OF_SCOPE 或分类失败）", "retryable": true }
}
```

字段说明：

- `kb_distribution`：块级多库分布 `{KB01: 2, KB04: 1}`，前端用于展示；
- `total_chunks`：成功入库的知识块总数；
- `blocks`：每个知识块的 `heading / kb_code / doc_id`；
- `kb_code / doc_id`：**仅当全部块归入同一知识库时返回**（自动分类恰好单库或手动指定），用于单库场景快捷定位。

错误码：404 任务不存在（`task_not_found`）、403 无权访问（`permission_denied`）。

## 4: 与 v1 的差异

| 项 | v1（人工选库） | v2（全自动分类） | 前端变化 |
|---|---|---|---|
| `POST /knowledge/upload` 的 `kb_code` | 必填（KB01~KB06） | 可选；不传 → 后台自动分类 | 默认不传，下拉可选指定 |
| `GET /knowledge/tasks/{id}` 的 `result` | `{doc_id, kb_code, total_chunks}`（单库） | `{kb_distribution, total_chunks, blocks, kb_code?, doc_id?}`（块级多库） | 展示总块数 + 多库分布 |
| 交互方式 | 同步等待 | 202 + 任务轮询 | `uploadDocumentAndWait()` 提交后轮询 |

---

## 5: 备注

- 浏览器不得直连知识库服务、分类服务或数据库（架构铁律），本接口由 Gateway 中转；
- 自动分类依赖 Gateway 侧的分类隧道（`scripts/classify_tunnel.py`）；分类服务不可用时任务将标记 `failed`（`classify_unavailable`），前端展示错误并允许重试；
- 前端轮询实现：`Finance_AI_Vue/src/services/api/knowledge.js` 的 `uploadDocumentAndWait()`（默认 1.5s 间隔，最多约 3 分钟，可被 AbortController 取消）。
